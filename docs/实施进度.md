### 模块 5：界面同步修复（移动后棋子停留在原地 / 点击棋子无反应）

| 子项 | 文件 | 状态 |
|---|---|---|
| 棋盘卡牌关闭射线检测，点击穿透到格子 | `Runtime/UI/BoardView.cs`、`Runtime/Cards/Card.cs`（`SetRaycastTarget`） | 完成 |
| 移动动画不再把棋子留在旧格 | `Runtime/Feedback/CardFeedback.cs`（`PlayMove` 的 `SetTarget`/`OnComplete`/`OnKill`、`Kill(complete:true)`）、`Runtime/UI/BoardView.cs`（`Place` 的位置校准） | 完成 |
| 销毁对象上的补间清理（消除 `RectTransform has been destroyed` 警告） | `Runtime/Cards/Card.cs`（`OnDestroy`） | 完成 |
| EditMode 契约用例 | `Tests/EditMode/BoardViewTests.cs`（2 个用例：移动后挂到目标格并纠正残留偏移；棋盘卡牌不抢点击） | 完成 |
| PlayMode 端到端用例 | `Tests/PlayMode/BoardMovePlayModeTests.cs`（3 个用例，含真实 `GraphicRaycaster` 射线命中断言） | 完成 |
| 流水线双模式 | `.github/workflows/unity-tests.yml`（`testMode` 矩阵加入 `PlayMode`） | 完成 |

根因与修法：

1. **点击被卡牌吃掉**：卡牌模板自带 `Image`、`Button` 与三个 TMP 文本，UGUI 射线会先命中卡牌并交给卡牌上的 `Button`（它没有任何监听），格子的 `Button` 永远收不到点击。实测射线命中顺序修复前为 `blade1(Clone) | Cell_0_0`，因此“点棋子选单位 / 点相邻牌换位 / 点自己的家”全部无反应。修复：棋盘卡牌统一 `SetRaycastTarget(false)`（只做显示），手牌保持可点。
2. **移动动画可能把棋子留在旧格**：`PlayMove` 先把卡牌摆到旧格位置再补间回格心，一旦补间没启动、被停止或被打断，卡牌就永久停在旧格附近，表现为“日志说移动了、棋子却在原地”；旧实现里 `DOKill()` 还会把动画停在半途。修复：调试用的位移补间加上 `SetTarget` 并挂 `OnComplete/OnKill` 把位移归零；`Kill` 改为 `DOKill(true)`（先写回结束值再停）；`Place` 在没有动画时把任何残留偏移校准回格心，于是“规则快照改变 → 界面必然跟随”。
3. **补间泄漏到已销毁对象**：手牌打出后立即被回收，模板上的选中/部署补间会在下一帧访问已销毁的 `RectTransform` 并打印 DOTween 警告。修复：`Card.OnDestroy` 停止自身补间（只停不补完，避免写回已销毁对象）。
