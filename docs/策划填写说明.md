# 策划填写说明：Spotlight.xlsx

本文面向策划，说明如何填写与维护正式数值来源 `Assets/Spotlight/Config/Spotlight.xlsx`。
规则本身以 [玩法.md](玩法.md) 为准；本文只描述“表格怎么填、工具怎么查错”。

## 1. 工作簿位置与基本流程

- 工作簿路径：`Assets/Spotlight/Config/Spotlight.xlsx`（Unity 工程根目录下的相对路径）。
- 固定 5 张工作表，名称必须完全一致：`Cards`、`Rules`、`Homes`、`BossSlots`、`Presentation`。多出或缺少任何一张表都会被拒绝。
- **`Deck` 工作表已废除**：抽牌堆改由 `Rules` 的 `drawPileSize` + 三阶级比例生成，携带哪些卡种由玩家开局时的“携带选择（选卡）”决定。旧工作簿里若还留着 `Deck` 表，读取阶段会直接报错并在修法里提示删除该表。
- 推荐流程（Unity 菜单）：
  1. `Tools/Spotlight/生成默认工作簿`：按本文第 6 节的默认数值重新生成工作簿（已存在时会先确认覆盖）。
  2. 用 Excel 编辑数值后先保存，再切回 Unity 验证/编译；无需关闭 Excel。编译读取磁盘上最近一次保存的内容，未保存的修改不会生效。需要定位文件时可用 `Tools/Spotlight/打开默认工作簿`。
  3. `Tools/Spotlight/验证配置`：只校验，不写任何资产；全部通过时输出“验证通过：配置可用。”，有错时一次性列出全部问题并在末行给出问题总数。
  4. `Tools/Spotlight/编译全部配置`：校验通过后生成只读配置资产与每卡种 Prefab。
  5. 进入 Play 或构建前会再次检查源文件摘要、生成资产是否缺失、Prefab 组合是否与配置一致；不一致会阻止运行并提示重新编译。
- 生成产物位于 `Assets/Spotlight/Generated/`（卡种资产与 Prefab 在 `Generated/Cards/`，主配置在 `Generated/Resources/`）。**不要手工修改生成产物**：改动会在下一次编译被覆盖，并且会被运行/构建门禁判定为过期或篡改。

## 2. 通用填写规则

- 第 1 行是表头，列名必须与下表完全一致（大小写敏感）；第 2 行起是数据。
- 列顺序可以调整，工具按表头名取列；但**不能出现未声明的列**，也不能有“有数据但没有表头”的列。
- 整行留空的行会被跳过，方便在工作表末尾留空行；表中间的空行同样安全。
- 单元格留空视为该类型的默认值：文本 = 空串、整数 = 0、小数 = 0、布尔 = false。必需列留空会在业务校验里报错。
- 布尔列填写 `true` / `false`（不区分大小写），也接受 `1` / `0`；不要填写“是/否”或中文。
- 整数/小数列使用 Excel 的“常规”或“数值”格式，直接输入数字，不要加前导单引号，也不必转成“文本形式的数字”。新生成的默认工作簿按列声明保存原生数字和布尔值；旧版文本数字仍兼容读取。
- 整数列必须是整数值，小数列可以写 `0.5` 这样的值，小数点用 `.`。编译后对应 C# / SO 字段为 `int`、`float` 或 `double`；ID、名称等文本字段仍是 `string`，开关为 `bool`。
- **正式数据单元格禁止公式**（包括共享公式）、禁止出现错误值（`#REF!` 等）、**禁止合并单元格**（第 1 行表头同样不允许合并）。
- 每张表的行数规则：`Cards` 至少 1 行；`Rules`、`Presentation` 恰好 1 行；`Homes` 恰好 2 行（player 与 boss 各一行）；`BossSlots` 恰好 3 行。
- 报错格式为 `文件!表:行:列 原因`，行号列号与 Excel 中看到的行列一致；报告按 文件 → 表 → 行 → 列 排序，便于逐条修复。

## 3. 各表列清单

### 3.1 `Cards`：卡种定义（每行一个卡种，每行生成一个 Prefab）

| 列名 | 类型 | 必需 | 取值与含义 |
|---|---|---|---|
| `id` | 文本 | 是 | 稳定 ID，全局唯一；字母开头，只允许字母、数字、`_`、`-`。改名不影响引用与升级关联 |
| `name` | 文本 | 是 | 展示名，非空；忽略首尾空格后不得与其他卡种重复 |
| `category` | 文本 | 是 | 只能是 `resource` / `attack` / `special` |
| `tier` | 文本 | 是 | 卡牌阶级，独立于 `category`：`basic`（初级）/ `intermediate`（中级）/ `advanced`（高级）；Boss 专用卡填 `none`（不适用），`none` 卡种不出现在携带选择里，因此不会进入抽牌堆。缺失、空白或非法值会在“验证配置”阶段报错，不按卡名或数值推断 |
| `adjacentClearanceComponent` | 布尔 | 是 | 是否启用四邻空格限制，默认 `false`。启用后该单位在部署、移动与互换前后，上下左右四邻中至少要有 `adjacentClearanceMinEmpty` 格为空；斜角不计，棋盘外按空计算。未启用时必须为 `false` 且阈值为 0。仅后羿-II综合舰为 `true` |
| `adjacentClearanceMinEmpty` | 整数 | 是 | 四邻中最少空格数，默认 0（关闭），启用时只能是 1～4。填 5 或负数直接报错；关闭时必须为 0。后羿-II综合舰填 `2` |
| `killActionComponent` | 布尔 | 是 | 是否启用击杀恢复行动，默认 `false`。启用后该单位的一次直接攻击（含伤害标记追加）击杀目标战斗单位时恢复一次普通行动，可连续触发，但不重开回合、未使用机会不跨回合保存。**仅攻击类卡可启用**。维京长船-2056 为 `true` |
| `damageMarkComponent` | 布尔 | 是 | 是否在直接攻击后施加伤害标记，默认 `false`。启用后每次直接攻击存活战斗单位使其获得 1 层；新层从下一次受伤起生效、永久保留可叠层，家不挂层。**仅攻击类卡可启用**，未启用时必须为 `false` 且每层伤害为 0。SNP-EU 为 `true` |
| `damageMarkDamagePerStack` | 整数 | 是 | 每层伤害标记在之后每次直接受伤时追加的伤害，默认 0（关闭），启用时为正整数。追加伤害不递归、不挂新层、不消耗炸弹预算。SNP-EU 填 `1` |
| `viewKey` | 文本 | 是 | 外观模板键，不能为空；改数值不会重建外观模板 |
| `hp` | 整数 | 是 | 初始生命与上限，必须 ≥ 1 |
| `atk` | 整数 | 否 | 攻击力，≥ 0；0 表示没有攻击能力 |
| `range` | 整数 | 否 | 曼哈顿攻击距离，≥ 0；0 表示不能攻击 |
| `moveDistance` | 整数 | 否 | 单次移动最大格数，≥ 0；0 表示不能移动，无玩法上的固定上限 |
| `produce` | 整数 | 否 | 每个己方回合产出，≥ 0 |
| `upkeep` | 整数 | 否 | 每个己方回合维持费，≥ 0 |
| `resourceComponent` | 布尔 | 否 | 是否启用资源组件；为 `false` 时 `produce`、`upkeep` 必须为 0 |
| `teleportComponent` | 布尔 | 否 | 是否启用传送组件；为 `false` 时 `permitsAttackDeploy` 必须为 `false` |
| `permitsAttackDeploy` | 布尔 | 否 | 是否允许己方攻击卡部署在其上下左右空格（星门用） |
| `deployHomeOnly` | 布尔 | 否 | 是否只能部署在己方边缘前两列 |
| `avoidAdjacentSameType` | 布尔 | 否 | 是否禁止部署在任何同卡种单位的四邻 |
| `requiresUpgrade` | 布尔 | 否 | 是否必须覆盖指定的己方资源单位才能部署；只有资源卡可以为 `true` |
| `upgradeFrom` | 文本 | 否 | 覆盖升级来源卡种 ID，必须指向**另一张资源卡**；`requiresUpgrade=false` 时必须留空 |
| `deploymentPenaltyComponent` | 布尔 | 是 | 是否启用一次性部署减攻组件，默认 `false`；旧工作簿必须显式补上本列 |
| `deploymentAttackReduction` | 整数 | 是 | 一次性部署减攻量，默认 `0`；启用组件时必须为正整数，禁用时必须为 0 |
| `deployCost` | 整数 | 是 | 成功部署这张卡的一次性资源消耗，默认 `0`，非负整数；资源不足时该目标不合法且不会高亮。Boss 部署不受此限制。开普勒-I/II 为 10 |
| `deployRequireAdjacentCategory` | 文本 | 否 | 部署时四邻（上下左右）必须存在的单位分类：`resource` / `attack` / `special`；默认留空表示无要求。数量为 0 时必须留空，数量大于 0 时必须填写 |
| `deployRequireAdjacentCount` | 整数 | 否 | 四邻中该分类单位的最小数量，默认 `0`；只统计在场战斗单位，不含家，不区分阵营 |
| `markOnEnterComponent` | 布尔 | 是 | 是否启用入场标记能力，默认 `false`；启用后半径与奖励必须为正整数，禁用时必须都为 0 |
| `markOnEnterRadius` | 整数 | 是 | 标记半径，默认 `0`；`1` 表示以自身为中心的 3×3 八邻（不含自己） |
| `markRewardResource` | 整数 | 是 | 被标记单位阵亡时给标记者阵营的资源，默认 `0`；只对“因战斗阵亡”发放 |
| `deathGrowthComponent` | 布尔 | 是 | 是否启用死亡加攻能力，默认 `false`；启用后加成与次数上限必须为正整数，禁用时必须都为 0 |
| `deathGrowthPerKill` | 整数 | 是 | 每次全棋盘单位阵亡时增加的攻击力，默认 `0` |
| `deathGrowthLimit` | 整数 | 是 | 最多触发次数，默认 `0`；是“触发次数上限”而不是“攻击力上限” |
| `attacksAlliesAsHeal` | 布尔 | 是 | 是否允许攻击友方并把友方结算改为治疗（生命 + 当前攻击，受上限限流），默认 `false`；仅攻击类卡可启用 |
| `leaveAfterDeploy` | 布尔 | 是 | 是否即时卡（部署即结算、结算即退场），默认 `false`；启用时 `deployGainResource` 必须为正整数。Boss 卡种与刷怪卡卡种不得指向即时卡 |
| `deployGainResource` | 整数 | 是 | 即时卡结算时立即获得的资源，默认 `0`；启用 `leaveAfterDeploy` 时必须为正整数 |

一次性部署减攻（`deploymentPenaltyComponent` + `deploymentAttackReduction`）：

- 启用的卡种上场后获得**一次**未消耗效果；随后同阵营攻击类卡牌成功上场时，按部署顺序取最早的一个来源，把新单位的攻击力降低该值（最低 0，不保留“剩余减攻”），来源标记为已消耗。
- 减攻持续到目标单位离场，跨回合与来源离场都不恢复；召唤失调、已行动与维持费不足都不阻止触发；回合开始与产出不会补充次数。
- 来源在触发前离场（阵亡、离场、被覆盖升级、被战机顶替），未触发效果一并消失。
- 资源卡、特殊卡、敌方单位与家都不会消耗效果；多个来源依次作用于连续上场的目标，同一目标最多承受一次。
- 正式数据里只有京都壹号（`kyoto_01`）启用该能力，减攻量 2；其余卡种必须填 `false` / `0`。

部署消耗与邻域部署要求（`deployCost` / `deployRequireAdjacent*`）：

- 部署消耗在**成功部署时一次性**扣除；资源不足时该目标不合法（高亮也不会出现），失败不扣资源、不消耗手牌。Boss 没有资源系统，Boss 部署不检查该值。
- 邻域要求只统计目标格四邻（上下左右）的在场战斗单位，**不含家、不区分阵营**；数量不足时该格不合法。该限制只约束部署，不限制部署后的移动或互换。
- 两者都是卡牌级字段，不产生能力组件；卡面显示“部署耗 N”，单位详情显示“部署消耗”“部署要求：四邻至少 N 个X单位”。
- 本次新增 8 个卡种：开普勒-I `kepler1`、开普勒-II `kepler2`、星铆-1复合着陆机 `landing1`（攻击卡）、后羿综合舰 `houyi1`、星棹-1收集系统 `collector1`、力场-I `force1`、比目鱼 `flounder1`、战时储备 `reserve1`（即时卡）；它们没有专属的“卡组”表需要登记（`Deck` 表已废除），卡种会自动进入对应阶级的可选池，是否携带由玩家开局选卡决定。

即时卡（`leaveAfterDeploy` + `deployGainResource`）：

- 仍需满足部署限制（目标格必须合法且为空），成功部署后立即获得 `deployGainResource` 资源，然后以“结算后离场”的原因离开棋盘。
- 在场时间视为 0：**不参与**一次性部署减攻与入场标记，**不触发**补兵、死亡加攻、标记奖励；来源卡照常进墓地，可反复抽到使用。
- 生命列对即时卡没有玩法意义，但 `Cards` 要求 `hp ≥ 1`，填 `1` 即可（建议在单元格批注里说明）。
- Boss 卡种（`Rules bossCardType`）、刷怪卡卡种（`Rules bossSpawnerCardType`）与阶段战舰（`Rules bossWarshipCardType`）**不得**指向即时卡，校验会直接报错。

治疗型攻击（`attacksAlliesAsHeal`）：

- 仅攻击类卡可启用；启用后合法攻击目标额外包含**己方单位**（不含自己与家）。
- 对友方的结算改为 `min(生命上限, 当前生命 + 当前攻击)`；满血也允许白打并照常消耗行动；射程与遮挡规则不变。
- 界面把这类目标用治疗色（特殊卡紫色）高亮，敌方目标仍是攻击色；规则层用 `LegalActions.Heal` 单列给视图，点击链路与普通攻击一致。

死亡加攻（`deathGrowthComponent` + `deathGrowthPerKill` + `deathGrowthLimit`）：

- 全棋盘**任一单位因战斗阵亡**时，在场且未达上限的该能力单位攻击力增加配置值；加成永久保留、跨回合不重置。
- 只有**因战斗阵亡**才触发；主动离场、被覆盖升级、被战机顶替都不触发。达到 `deathGrowthLimit` 次后不再增加（已获得的加成不回收）。
- 同样不生成 Prefab 组件，只在卡种资产上生成 `<id>_DeathGrowth` 子资产；单位详情显示“死亡加攻：已触发 N/L”。

入场标记（`markOnEnterComponent` + `markOnEnterRadius` + `markRewardResource`）：

- 启用后该单位上场时把半径内的其它单位标记为“自己阵营”，移动或互换进入范围也会被标记；标记**永久保留**、多来源**先到先得、不叠加**。
- 只有**因战斗阵亡**才发放奖励；主动离场、被覆盖升级、被战机顶替都不算阵亡。Boss 侧暂无资源系统，Boss 标记不产生资源。
- 能力是纯规则能力，**不生成 Prefab 组件**，只在卡种资产上生成 `<id>_MarkOnEnter` 子资产；界面通过 `UnitState.MarkedBy` 显示“已被标记”。

四邻空格限制（`adjacentClearanceComponent` + `adjacentClearanceMinEmpty`）：

- 只统计上下左右四邻，斜角不计；棋盘外四个方向直接算空（边缘自带 1 空、角落自带 2 空），家和战斗单位算占用，炸弹不算。
- 部署只看目标格；移动同时看起点（原布局）与落点（旧格已腾空、新格已占用的最终布局）；互换看交换前后，并且双方中所有具有该能力的单位都要满足；路径中间格不检查。
- 被围后仍可攻击，只是不能移动与互换；其它单位可以靠近围堵它。阈值只能是 1～4，关闭时必须为 0。
- 纯规则能力，**不生成 Prefab 组件**，只在卡种资产上生成 `<id>_AdjacentClearance` 子资产。正式仅后羿-II综合舰启用（2）。

击杀恢复行动（`killActionComponent`）：

- 直接攻击（含伤害标记追加）击杀目标战斗单位后恢复该单位一次普通行动；可连续触发、无每回合次数上限，未使用机会不累计。
- 恢复不是重开回合：不抽牌、不产资源、不重复扣维持费、不影响其它单位与出牌次数。
- 炸弹击杀、其它单位击杀、主动离场、覆盖升级、战机顶替都不触发；仅攻击类卡可启用。
- 没有数值参数，**不生成 Prefab 组件**，只在卡种资产上生成 `<id>_KillAction` 子资产（子资产存在即启用）。正式仅维京长船-2056 启用。

伤害标记（`damageMarkComponent` + `damageMarkDamagePerStack`）：

- 只有直接攻击**存活的战斗单位**才挂 1 层；家、治疗与炸弹不挂层，追加伤害不挂新层。
- 层永久保留、可叠层、不设玩法上限；本次受伤按受伤前层数结算，新层从下一次受伤起生效；每层数值在施加时复制，来源离场不影响。
- 与“入场标记”是两种不同机制：入场标记决定阵亡发资源，伤害标记决定每次直接受伤追加伤害；不要复用 `markOnEnter*` 列。
- 纯规则能力，**不生成 Prefab 组件**，只在卡种资产上生成 `<id>_DamageMark` 子资产。正式仅 SNP-EU 启用（每层 1 点）。

### 3.2 `Rules`：全局规则（恰好 1 行）

| 列名 | 类型 | 必需 | 取值与含义 |
|---|---|---|---|
| `rows` | 整数 | 是 | 棋盘行数，≥ 1 |
| `columns` | 整数 | 是 | 棋盘列数，≥ 2 |
| `homeRegionWidth` | 整数 | 是 | 己方区域宽度（列），必须在 1..`columns` 之间 |
| `playerPlays` | 整数 | 是 | 玩家每回合出牌次数上限，≥ 0 |
| `bossPlays` | 整数 | 是 | Boss 每回合放牌次数上限，≥ 0 |
| `drawCount` | 整数 | 是 | 玩家每回合抽牌数，≥ 0；0 表示不抽牌 |
| `handLimit` | 整数 | 是 | 手牌上限，≥ 0；结束回合超限必须先弃牌 |
| `initialResources` | 整数 | 是 | 初始资源，≥ 0 |
| `bossRespawnDelay` | 整数 | 是 | 兵位阵亡后的补兵间隔（完整回合数），≥ 1 |
| `bossBombInterval` | 整数 | 是 | 炸弹部署间隔（完整回合数），≥ 1，默认 10；第 10、20……回合玩家行动前部署 |
| `bossBombDamage` | 整数 | 是 | 整颗炸弹共享伤害预算，≥ 1，默认 3；下一完整回合玩家行动前引爆 |
| `bossBombColumn` | 整数 | 是 | 屏幕左起列号（从 1 开始），≥ 1，默认 5；实际取 min(配置值, floor(columns / 2)) |
| `playerSide` | 文本 | 是 | 玩家所在边缘，只能是 `left` / `right` |
| `firstSide` | 文本 | 是 | 先手方，只能是 `player` / `boss` |
| `bossCardType` | 文本 | 是 | Boss 使用的卡种 ID，必须已在 `Cards` 注册；AI 模式下必须是攻击卡，手动模式可用任意已注册卡种 |
| `playerControlsBoss` | 布尔 | 是 | 是否由玩家手动操作 Boss |
| `accumulateResources` | 布尔 | 是 | 资源是否跨回合累积；`false` 表示每回合开始清零 |
| `summoningSickness` | 布尔 | 是 | 新部署单位当回合是否不能行动 |
| `adjacentSwap` | 布尔 | 是 | 是否允许相邻己方非资源单位互换位置；资源卡始终不参与互换 |
| `lineBlocking` | 布尔 | 是 | 是否开启同一行/列的单位遮挡 |

抽牌堆规则（7 列，追加在 `bossSpawnerSpawnCardType` 之后）：

| 列名 | 类型 | 必需 | 默认值 | 取值与含义 |
|---|---|---|---|---|
| `drawPileSize` | 整数 | 是 | 24 | 玩家抽牌堆总张数，必须 ≥ 3。开局按此数量生成卡牌记录；“抽牌堆 + 手牌 + 墓地”的总数恒等于它 |
| `tierRatioBasic` | 整数 | 是 | 70 | 初级卡占抽牌堆的百分比，必须 ≥ 1 |
| `tierRatioIntermediate` | 整数 | 是 | 20 | 中级卡占抽牌堆的百分比，必须 ≥ 1 |
| `tierRatioAdvanced` | 整数 | 是 | 10 | 高级卡占抽牌堆的百分比，必须 ≥ 1 |
| `maxTypesBasic` | 整数 | 是 | 5 | 玩家每局最多携带的初级**卡种数量**，必须 ≥ 1 |
| `maxTypesIntermediate` | 整数 | 是 | 3 | 玩家每局最多携带的中级**卡种数量**，必须 ≥ 1 |
| `maxTypesAdvanced` | 整数 | 是 | 2 | 玩家每局最多携带的高级**卡种数量**，必须 ≥ 1 |

这三组数字一起决定抽牌堆，填完之后**不需要再填任何“每种卡几张”**：

- 张数怎么分：每阶级先按 `floor(张数 × 比例 / 100)` 取整，每阶级至少 1 张；合计不足张数时缺额全部给初级，超出（只可能由保底抬升造成）时从张数最多的阶级扣、平手按高级→中级→初级、每阶级保底 1 张；最后把每阶级张数均分给该阶级已选卡种，余数按 `Cards` 表顺序发给靠前卡种，每个被选卡种至少 1 张。
- 例：24 张 @70/20/10 → 初级 18 / 中级 4 / 高级 2；张数填 3 → 1 / 1 / 1。
- 有效携带上限 = min(配置上限, 该阶级卡种数)，因此某阶级的可选卡种池暂时只有 1 种时不必把上限改成 1。

三条硬校验（不满足就阻止“验证配置”）：

1. `drawPileSize` ≥ 3，三个比例各自 ≥ 1 且**合计必须为 100**（不支持 0%）。
2. 每个阶级至少要有一个可携带卡种（`Cards` 里 `tier` 不是 `none` 的行），否则报“该阶级没有任何可携带卡种”。
3. 按比例算出的每阶级张数不得少于该阶级的有效携带上限，否则报“分到的张数少于携带上限”。这条保证玩家把上限勾满时，每个被选卡种都能真的抽到。

| `缺失必需列：drawPileSize` / `tierRatioBasic` / `maxTypesBasic` 等 | 旧工作簿缺少抽牌堆的 7 列 | 按本文第 3.2 节补上这七列（默认 24 / 70 / 20 / 10 / 5 / 3 / 2） |
| `Rules drawPileSize：抽牌堆张数必须至少为 3` | 张数填了 0、1、2 或留空 | 填 ≥ 3 的整数（默认 24） |

| `Rules tierRatioBasic/Intermediate/Advanced：三阶级比例之和必须为 100` | 三个比例加起来不等于 100 | 把三者调成合计 100（默认 70 / 20 / 10） |
| `Rules maxTypesBasic/Intermediate/Advanced：三阶级携带上限都必须至少为 1` | 某个携带上限填了 0 或留空 | 三个上限都填 ≥ 1 的整数（默认 5 / 3 / 2） |
| `Cards tier：初级（或中级 / 高级）没有任何可携带卡种，请至少配置一张…` | 某阶级的卡种全被删了（或全填成 `none`） | 在该阶级补一个卡种，或重新分配 `tier` |
| `Rules：按 drawPileSize 与阶级比例，中级（或初级 / 高级）只能分到 N 张，少于携带上限 M 种；请调整比例或上级上限` | 比例算出的张数装不下该阶级的携带上限，勾满会有卡种一张也抽不到 | 调大该阶级比例 / 调大 `drawPileSize` / 调小该阶级 `maxTypes*` |
| `Rules：棋盘至少 1 行 2 列，格数不能溢出` | `rows`/`columns` 太小或过大 | 行 ≥ 1、列 ≥ 2，且行×列不超过整数上限 |
| `Rules homeRegionWidth：必须在 1 至列数之间` | 区域宽度大于列数或小于 1 | 填 1..`columns` |
| `Rules：次数/资源不可为负，bossRespawnDelay 至少为 1` | 某个次数/资源为负，或补兵间隔为 0 | 次数与资源 ≥ 0，补兵间隔 ≥ 1 |
| `Rules playerSide：只能为 left/right` | 填了 `Left`、`左边` 等 | 填小写 `left` 或 `right` |
| `Rules firstSide：只能为 player/boss` | 填了其他值 | 填小写 `player` 或 `boss` |
| `Rules bossCardType：AI 必须使用攻击卡，手动模式必须使用已注册卡种` | Boss 卡种未注册，或 AI 模式下填了非攻击卡 | 先把卡种加入 `Cards`；AI 模式改用攻击卡 |
| `Homes：阵营唯一、生命正数、产出非负且 Boss 产出为零` | 少了 player/boss 某一行、家了重复、生命 ≤ 0 或 Boss 家产出不为 0 | 保证两行且数值合法 |
| `BossSlots：ID、行比例或边缘偏移非法` | 兵位 ID 为空/重复、`rowFraction` 超出 0..1、`edgeOffset` 为负或不小于 `homeRegionWidth` | 按第 3.4 节修正 |
| `Presentation：尺寸/字号/日志数/动画参数非法` | 某整数 ≤ 0，动画时长为负，放大倍率 ≤ 0 | 按第 3.5 节修正 |
| `Presentation xxx：需要 #RRGGBB 或 #RRGGBBAA` | 颜色写成了颜色名或缺少 `#` | 改为 `#RRGGBB` / `#RRGGBBAA` |
| `无法解析 xlsx：Sharing violation ...` | 旧版 XML 检查器不允许 Excel 同时持有可写句柄，属于文件共享问题，与数字/文本类型无关 | 使用修复后的检查器；编辑后先保存，再验证/编译，无需关闭 Excel |
| `找不到工作簿，请先执行 Tools/Spotlight/生成默认工作簿` | 工作簿被移动或删除 | 重新生成，或把文件放回 `Assets/Spotlight/Config/Spotlight.xlsx` |
| 配置门禁提示“配置已过期” | 编辑工作簿后没有重新编译 | 执行 `Tools/Spotlight/编译全部配置` |
| 配置门禁提示“生成资产缺失/不匹配” | 手工删除或改动了 `Assets/Spotlight/Generated/` 内容 | 重新编译；不要手工编辑生成产物 |

## 7. Boss 刷怪卡配置

一阶段技能使用 Rules 的五个触发和部署字段；生成卡种已迁移到每张卡的 Cards 配置。中文说明放在表头批注中；Cards 的刷怪卡生命单元格也有批注。不要插入说明行、公式或额外工作表。默认生成器同样保留这些批注。

| 字段 | 默认值 | 填写与生效规则 |
|---|---|---|
| `bossSpawnerAttackThreshold` | 12 | 正整数。Boss 回合开始统计全部玩家在场单位的总攻击力，大于等于此值才继续检查数量。 |
| `bossSpawnerCountFromColumn` | 4 | 正整数。数量统计从玩家一侧第 1 列起算，含本列及之后；只统计 category=attack。 |
| `bossSpawnerUnitThreshold` | 2 | 正整数。指定列范围的玩家攻击类单位数量下限。 |
| `bossSpawnerDeployFromColumn` | 5 | 正整数。刷怪卡部署区域从玩家一侧起算，含本列及之后的空格。 |
| `bossSpawnerCardType` | `bossSpawner` | 已注册特殊卡 ID。生命正数，攻击、射程、移动为 0，无资源、传送及升级能力；改名不改变引用。 |
| Cards `spawnComponent` | false | 是否具有通用刷怪能力；刷怪笼和战舰为 true。 |
| Cards `spawnCardType` | 空 | 启用刷怪时引用攻击类卡种；刷怪笼和战舰均为 `bossCombat`。旧 Rules `bossSpawnerSpawnCardType` 必须迁移至这里并删除旧列。 |
| Cards `canAttackResources` | true | 是否可直接攻击敌方资源单位；战舰为 false，仍可攻击敌方家；友方治疗保持独立。 |
| Cards `canSwap` | true | 是否允许互换；刷怪笼为 false，战舰为 true，资源分类仍不可互换。 |
| Rules `bossPhaseTwoHp` | 20 | 大于 0 且小于 Boss 初始生命；伤害跨阈值时截断并立即进入锁血阶段。 |
| Rules `bossWarshipColumn` | 8 | 从玩家一侧起算，必须在棋盘内；部署行取三等分点，默认第二、第四行。 |
| Rules `bossWarshipCardType` | `bossWarship` | 战斗与刷怪能力组合，默认生命 15、攻击 2、射程 1、移动 1、tier=none；不得配置成即时卡。 |

刷怪卡生命在 Cards 对应行的 `hp` 配置，默认 1。刷怪卡阶级为 `none`，不会出现在携带选择里，也不会被玩家抽到。一阶段技能场上同时最多一张普通刷怪笼，固定不动、不能互换；部署后的下一个 Boss 回合开始，每回合在八邻生成一架战机，满格时随机顶替玩家单位，无目标则暂停并在下回合重试。阶段战舰也使用该刷怪能力，但可移动、攻击和互换；二阶段两艘指定战舰全部阵亡后解除锁血并进入三阶段。已有单位的标记奖励、死亡加攻和友方治疗能力继续按原规则生效。

两个列号超过棋盘宽度时范围为空，不自动钳制。旧 Excel 和调试 JSON 必须补齐新字段及引用卡种才能通过校验；更新后执行验证及编译，不能手改 Generated。调试面板的修改只作用于本次运行会话，成功“应用并重开”后生效。
