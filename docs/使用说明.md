# 使用说明：Spotlight 首版

本文面向开发者与测试，说明如何在本机跑起首版、如何操作一局、调试面板能用什么，以及常见问题如何排查。
玩法规则见 [玩法.md](玩法.md)，表格填写见 [策划填写说明.md](策划填写说明.md)，实现设计见 [最初版本实现方案.md](最初版本实现方案.md)。

## 1. 环境与依赖

| 项目 | 值 | 说明 |

## 2. 首次运行步骤（按顺序执行）

在 Unity 菜单中选择：

1. `Tools/Spotlight/生成默认工作簿`
   在 `Assets/Spotlight/Config/Spotlight.xlsx` 写出 5 张默认表（`Cards` / `Rules` / `Homes` / `BossSlots` / `Presentation`，`Deck` 表已废除；目标文件已存在时会先确认覆盖）。可用 `Tools/Spotlight/打开默认工作簿` 直接打开该文件。
2. 按 [策划填写说明.md](策划填写说明.md) 编辑工作簿（可选；默认值即可直接运行）。
3. `Tools/Spotlight/验证配置`
   只校验不写资产。全部通过时输出“校验通过”；有错时在 Console 一次性列出全部问题，格式为 `文件!表:行:列 原因`。
4. `Tools/Spotlight/编译全部配置`
   校验通过后生成只读配置资产与每卡种 Prefab；Console 会输出“编译完成，生成 N 个资产”。任何一项校验失败都不会改动已有产物。
5. `Tools/Spotlight/生成中文字体资产`
   生成 TMP/TextCore 字体资产与界面用的 PanelSettings；首次在干净工程运行前可先执行 `Tools/Spotlight/导入 TMP 基础资源`。
6. `Tools/Spotlight/生成演示场景`
   生成 `Assets/Spotlight/Scenes/Spotlight.unity` 并写入 Build Settings 第一位（会先确保字体资产与配置已编译）。可选：`Tools/Spotlight/重建外观模板` 用于重建卡牌外观模板。
7. 打开 `Assets/Spotlight/Scenes/Spotlight.unity`，点击 Play 运行。
   场景根节点上的 `GameBootstrap` 负责“加载配置 → 创建对局 → 绑定视图”；若配置缺失或非法，界面会显示“无法开局：…”而不是静默半初始化。
8. 每一次启动（每次进入 Play）都会先弹出“携带选择”：勾选本次携带的卡种（每阶级至少 1 种、最多到行首 `已选/上限` 表示的上限），点“确认并开局”后才进入对局。选卡不持久化，重新启动就要重选。

### 2.1 卡图（`Cards.cardArt`）

卡牌默认只有分类底色，没有立绘。给卡种配卡图：

1. 把 PNG 放进 `Assets/Imported/SpotlightArt/CardArt/`（也可放任意位置，只要在表里写完整路径）。
   Inspector 里把 **Texture Type** 设为 **Sprite (2D and UI)**，其余按需（建议关 Mipmap、Max Size ≥ 1024）。
   PNG 由 Git LFS 管理，提交前确认 `git status` 里是 LFS 指针。
2. 在 `Cards` 表的 `cardArt` 列填文件名（如 `ge1.png`）或 `Assets/` 开头的完整路径；留空表示这张卡没有卡图。
3. 老工作簿没有这一列时可直接加在 `spawnCardType` 右边（该列可选，缺列也能编译），或重新执行“生成默认工作簿”后补数据。
4. `Tools/Spotlight/验证配置` → `Tools/Spotlight/编译全部配置`。
   首次在旧工程上编译会顺带给外观模板补一个 `Art` 子节点（幂等，不会覆盖手工外观），也可以用菜单 `Tools/Spotlight/升级卡牌外观模板` 单独执行。
5. 卡图缺失或写法非法会让“编译全部配置”直接失败并给出卡种 ID，不会静默回退成纯色。

卡图建议 3:4（如 600×800）：手牌卡面固定 120×160，棋盘上会被压成“格子尺寸 − 8”，节点已开启 `preserveAspect`，比例不一致只会在内侧留边而不会变形。卡图不参与规则结算，也不影响任何数值。


## 3. 程序集与目录结构

| 程序集 | 目录 | 引用 | 说明 |
|---|---|---|---|
| `Spotlight.Core` | `Assets/Spotlight/Core/` | 不引用引擎（`noEngineReferences`） | 配置契约与校验、对局状态、`GameSession` 规则内核与 Boss AI |
| `Spotlight.Runtime` | `Assets/Spotlight/Runtime/` | `Spotlight.Core`、TMP、uGUI | `Card` 与五个能力组件、配置 SO 与加载、UI 视图、动效、调试面板 |
| `Spotlight.Editor` | `Assets/Spotlight/Editor/` | 编辑器程序集，仅编辑器编译 | Excel 读取/校验/编译、资产发布、默认工作簿、外观模板、字体与菜单、运行与构建门禁 |
| `Spotlight.Tests.EditMode` | `Assets/Spotlight/Tests/EditMode/` | `Spotlight.Core`、`Spotlight.Runtime`、`Spotlight.Editor` | EditMode 行为与配置测试（仅 Editor 平台） |

依赖方向单向：Tests → Editor → Runtime → Core。运行层不得引用编辑器或测试程序集。

生成产物（只读，禁止手工修改）：

- `Assets/Spotlight/Generated/Cards/<id>.asset`：卡种定义 SO，能力组件配置作为子资产保存（`<id>_Combat` / `_Resource` / `_Teleport` / `_DeploymentPenalty` / `_Spawn`，未启用的能力不生成子资产）。
- `Assets/Spotlight/Generated/Cards/<id>.prefab`：卡种 Prefab，保存组件组合与 SO 引用，不重复存储数值。
- `Assets/Spotlight/Generated/Resources/SpotlightConfig.asset`：主配置资产，运行时通过 `Resources/SpotlightConfig` 加载。**它不记录工作簿路径/摘要/编译时间**：本资产会被打进正式包，那三项会随包泄露开发期信息，因此只保留在不进包的 `ConfigManifest.asset` 里。
- `Assets/Spotlight/Generated/ConfigManifest.asset`：编译清单，记录源工作簿路径、源文件摘要（SHA256）、编译时间与全部产出路径（该资产不在 `Resources/` 下、运行时不被引用，因此不进包，只供门禁与菜单使用）。
  它的类型也在编辑器程序集里（`Assets/Spotlight/Editor/ConfigManifest.cs`）——放在运行层时，它的 `_sourceWorkbookPath` / `_sourceHash` / `_compiledAtUtc` **字段名**会随 `Spotlight.Runtime.dll` 一起进包。

## 4. 玩法操作说明

- **开局选卡（携带选择）**：启动后先出现“携带选择”面板，按阶级分组列出全部 `tier != none` 的卡种。点“携带 / 取消”勾选，每行右侧显示本局张数（“本局 ×N”），底部预览显示“抽牌堆 N 张 → 初级 a / 中级 b / 高级 c”并随勾选实时重算。每阶级至少带 1 种，最多带到阶级行首 `已选/上限` 里的上限，达上限后同类按钮置灰；“恢复默认”按上限取满。面板上没有“取消”：必须先选才能开局。卡种**按阶级分组**显示（初级绿、中级蓝、高级紫）：每组左侧有与阶级同色的竖条、组首是阶级徽章与“已选/上限 · 本阶级抽牌堆张数”，组内每行还带“初/中/高”短标，因此不必回看标题也能确认某张卡的阶级。
- **出牌**：点击手牌选中并查看可部署范围；按住鼠标左键拖动手牌，在合法格松手部署，也可以直接按住未选中的手牌拖动。拖动时保留全部合法格高亮，鼠标所在的合法格额外显示描边；在非法格、格子间隙或棋盘外松手，卡牌会回到手牌原位置并保持选中。点击格子不会部署手牌。升级卡高亮的是可被覆盖的己方目标；星门在场时会额外高亮其上下左右。再次点击同一张已选中的手牌可取消选中，部署高亮随之消失。暂停、结束回合、重开或切出游戏窗口会取消当前拖动；弃牌阶段仍通过点击手牌弃牌，拖动不会弃牌。
- **选中单位**：点击棋盘上的单位，棋盘下方显示完整名字、生命、攻击、射程与移动距离；可移动格、可攻击目标、可互换目标分别以不同颜色高亮。再次点击同一个单位可取消选中，高亮随之消失。
- **移动/攻击**：选中己方单位后点击高亮格移动（按最短可通行路径，允许转弯），或点击高亮敌方目标/家攻击。移动或攻击后本回合不能再行动。
- **互换**：选中己方单位后，相邻可互换的己方卡牌以紫色高亮，点击即交换位置；双方本回合都不能再行动。资源卡不参与互换：选中资源卡时相邻己方卡牌不会出现紫色高亮，点击只会切换选中对象。未开启 `rules.adjacentSwap` 时点击其他己方卡牌同样只切换选中对象。
- **界面布局（战斗界面）**：顶部是回合数 / 资源 / 剩余出牌，其下紧贴一个齿轮；棋盘左右两侧各有一块详情区，选中我方卡牌显示在左侧、选中敌方单位显示在右侧（选中家时不显示，区域平时为空但保留占位）；手牌同一行左侧是“墓地”计数，右侧是“抽牌堆”三行计数与“结束回合”。**抽牌堆按阶级分行显示实时剩余张数（高级 N / 中级 N / 初级 N）**，开局时等于选卡生成的构成，抽牌后递减、墓地洗回后回涨；**墓地仍只显示总数**，两者不是同一口径。棋盘大小维持原状。
- **齿轮菜单**：点击齿轮即暂停对局（期间棋盘与手牌都不接受操作），屏幕中间出现“继续”“选卡”“重开”和“退出游戏”（只在编辑器里多一个“配置/调试”）；菜单打开时界面切换成菜单视图：只保留对局日志（战斗界面下默认折起）；原来的右下角“Boss 状态 / 选中详情”侧栏已删除，Boss 阶段与锁血看顶部常驻摘要、选中详情看左右卡面详情区。
- **菜单选卡**：点“选卡”会先弹二次确认（“进入选卡？确认后当前对局将重开，进度不会保留。”，两个按钮为“进入选卡”/“继续当前对局”）；确认后重新选卡并按新卡组重开对局，选“继续当前对局”则回到菜单。
- **退出游戏**：点击齿轮菜单里的“退出游戏”直接离开本次运行（编辑器里结束 Play、正式包里关闭程序）。当前对局不保存，也不会返回棋盘，请先确认不需要接着打。
- **离场**：点击棋盘上自己的单位选中它，左侧详情区（显示该卡卡面）下方会出现“离场”按钮，点击即把该单位移出棋盘。离场不消耗它的本回合行动（移动/攻击之后仍可离场），来源卡不会回到手牌；Boss 单位与家不会出现这个按钮。
- **家移动**：己方回合点击自己的家，可在己方区域内上下左右移动一格（每回合一次，不消耗资源与出牌次数）。再次点击自己的家可取消选中。
- **高级卡：四邻空格限制 / 击杀恢复 / 伤害标记**：后羿-II综合舰在四邻不足 2 空时不能部署、移动或互换（被围后仍可攻击），非法格不会高亮，拖放失败会回到手牌；维京长船-2056 击杀目标后卡面仍可操作，可直接点击下一个高亮目标继续行动，但不会重新抽牌或产资源；SNP-EU 攻击后目标卡面会在属性行末尾显示“标 N”，左侧/右侧详情显示当前层数与下次直接受伤追加的总量。完整规则见 [玩法.md](玩法.md) 的高级卡章节。
- **结束回合**：点击“结束回合”（位于抽牌堆三行计数右侧）。若手牌超过上限，先进入弃牌阶段：点击手牌弃至上限后才能进入对手回合。结束回合（含手动 Boss 的“跳过放牌并结束”）会同时清空当前选中，棋盘与手牌都会恢复未选中外观。
- **Boss 模式**：默认 AI 控制，Boss 回合自动结算（读取刷怪条件 → 恢复已有行动 → 已有刷怪卡生成战机 → 新刷怪卡部署 → 固定兵位补兵 → 普通行动 → 自动结束），界面隐藏 Boss 操作按钮并显示兵位计时。勾选“玩家控制 Boss”后进入手动模式：先处理刷怪卡机会，再放牌、移动、攻击 Boss 单位与家；未放足时可点击“跳过放牌并结束”。手动模式下可在棋盘右下角选择“部署刷怪卡”或“跳过刷怪卡”。
- **重开**：点击齿轮菜单里的“重开”，或对局结束后的“再来一局”重新开局，两者都沿本次已选卡组，不再弹选卡界面（若确实要换卡，用菜单里的“选卡”）。对局日志（在齿轮菜单里）记录每次行动的坐标与结果。

## 5. 对局配置面板（只在编辑器内）

> 该面板**不是“正式包里隐藏”而是“正式包里不存在”**：`Editor/Debug/` 下的 `ConfigDebugPanel.cs`、`ConfigFieldBuilder.cs`、`DebugConfigDraft.cs` 与安装器 `ConfigPanelInstaller.cs` 编进 `Spotlight.Editor`（仅编辑器平台），面板是普通类、由安装器在进入 Play 时 `new` 出来并挂到 HUD 根节点上；面板骨架**用代码搭建**（不是 UXML 资产）；两个入口按钮只在 `#if UNITY_EDITOR` 里由 `HudView` 用代码插入。
>
> 为什么不放在 `Runtime/` 里配 `#if`：`#if` 只能把代码从 `Spotlight.Runtime.dll` 去掉，Unity 仍会按编辑器编译结果在 `globalgamemanagers.assets` 写出这些**类名**（实测）。搬进仅编辑器程序集后，包的 DLL、sharedassets 与类型目录里都查不到配置面板的任何痕迹。

面板是**表单式**的，字段分组与既有网页版配置界面一致；JSON 只作为导入导出通道保留，日常调数值不需要写 JSON。

- 入口：齿轮菜单里的“配置/调试”按钮（先点左上角齿轮进入菜单）；开发时也可以直接用菜单 `Tools/Spotlight/在运行中打开配置面板`（仅 Play 模式有效）。统一判定集中在 `DebugSupport.IsDebugAvailable`，但真正保证正式包干净的是条件编译：`DebugSupport` 只负责“同一个调试构建里按钮要不要显示”。
- 面板打开时会同时启用界面遮罩与规则层输入闸门，棋盘不会被误点。
- 分区与字段（自上而下）：
  1. **棋盘**：行数、列数（输入时自动夹紧到合法区间）。
  2. **家**：玩家所在边缘、双方家血量、玩家家每回合产出。
  3. **抽牌堆（选卡与阶级比例）**：抽牌堆张数（默认 24，至少 3）、三阶级比例（默认 70 / 20 / 10，三者之和必须为 100，不支持 0%）、三阶级携带上限（种，默认 5 / 3 / 2）；下方实时汇总“抽牌堆 N 张 → 初级 a 张 / 中级 b 张 / 高级 c 张”。分区下半是**调试用强制牌堆**：任一卡种填大于 0 的张数即整体覆盖抽牌堆（与开局选卡结果无关），全部为 0 表示按选卡结果生成，旁边有“清空强制牌堆”。强制牌堆仅本次运行会话有效，不写入任何资产。
  4. **资源卡 / 玩家战斗卡 / 特殊卡**：每个卡种一个卡片，字段为名字、卡牌阶级（初级/中级/高级，Boss 专用卡为不适用）、（资源卡）每回合产出、每回合消耗资源（维持费）、生命、攻击力、攻击距离（曼哈顿）、移动距离；特殊卡额外提供“仅可部署在己方前两列”“四邻不能有同卡种单位”“允许己方战斗卡部署在上下左右空格”；资源卡勾选“需要覆盖升级其它资源卡”后会出现目标卡下拉。所有卡种还可配置“四邻空格限制（1～4 空）”；攻击类卡额外提供“击杀恢复行动”和“伤害标记（每层追加伤害）”。关闭这些开关时对应数值自动清零，非法组合（例如非攻击卡启用击杀恢复）会阻止“应用并重开”。每个分区右上角有“新增资源卡/新增战斗卡/新增特殊卡”，新卡按 `custom_分类_序号` 命名、默认初级。**逐卡种数量已不再存在**：抽牌堆只由张数 + 阶级比例推导，具体带哪些卡在开局选卡时决定。
  5. **Boss 战斗卡**：玩家控制 Boss、AI 阵亡补卡间隔、名字与四项属性。
  6. **回合规则**：每回合抽牌数、手牌上限、每回合出牌上限、Boss 每回合放牌数（仅手动模式）、先手。
  7. **开关**：资源跨回合累积、刚上场的单位当回合不能行动、同列/同行单位遮挡攻击、相邻己方卡牌可互换位置。已确认删除的反击与斜移不会出现在界面上。
  8. **JSON 导入 / 导出**：“复制 JSON”把当前草稿完整复制到系统剪贴板，可粘贴到文本文件保存；导入前先复制文件中的全部 JSON，再点击“从剪贴板导入”。面板不显示 JSON 全文，避免大配置超过 UI Toolkit 单元素文本顶点上限；不会截断导出数据。导入仅修改草稿，仍需“应用并重开”才影响对局；失败保留原草稿和强制牌堆。文档版本 `schemaVersion` 升到 2，旧版本 JSON 会被直接拒绝；导入旧格式时会在提示里列出被移除的字段（`cost`、`diagonalMove`、`counterAttack`、`chainDeployOnly`、旧家坐标 `row`/`col`，以及整段废弃的 `deck` 数组），且布尔/数值字段类型非法会直接拒绝导入。
- 校验是**实时**的：任何非法输入都会在标题下方显示原因，并置灰“应用并重开”。
- “恢复默认”：把草稿恢复为 Excel 编译产物；“关闭”：收起面板但**保留草稿**，重新打开可继续编辑。
- “应用并重开”：先创建候选对局并检查 Boss 卡种，成功后才替换当前对局并重开；失败时保留原对局与草稿，并把原因写在面板状态区。若新配置让当前选卡变非法（例如把某阶级的卡种删光、或改小携带上限），会**静默回退默认选卡**（每阶级按有效上限取满、按 `Cards` 表顺序），不再弹选卡界面。
- 数据隔离：草稿、JSON 文本与临时卡种只存在于内存，退出 Play 或重启程序后丢弃；调试不会修改 `Spotlight.xlsx` 与生成资产，也不会保存战斗进度。面板只能通过“关闭”或成功“应用并重开”退出，点击面板外背景不会关闭。

界面截图：`docs/配置面板.png`、`docs/配置面板-下半部分.png`。

### 卡牌阶级配置

`Assets/Spotlight/Config/Spotlight.xlsx` 的 `Cards.tier` 为必填文本：`basic`（初级）、`intermediate`（中级）、`advanced`（高级），Boss 专用卡填 `none`（不适用）。此字段独立于资源/攻击/特殊类型，不建立卡组包分类。

当前六种玩家卡（GE-1、GE-12、尖刀1、灵兔2、奥德修斯-1、京都壹号）为初级；中级为开普勒-I、开普勒-II、星铆-1复合着陆机、后羿综合舰、星棹-1收集系统、力场-I、比目鱼、战时储备；高级为星门、后羿-II综合舰、德克萨斯游骑兵、维京长船-2056、SNP-EU、拿破仑-1769。卡牌与单位详情显示阶级，卡面布局和类型配色保持原样。阶级决定抽牌堆构图：张数按比例分到三个阶级，再均分给该阶级已选卡种（3 张同种初级卡计作 3 张初级卡）。携带上限作用在**卡种数量**上（`Rules` 的 `maxTypes*`，有效上限 = min(配置上限, 该阶级卡种数)），不限制使用回合；`none` 卡种不出现在携带选择里，因此不会被抽到。

修改后按“验证配置 → 编译全部配置”发布，生成资产不得手改。旧工作簿缺 `tier` 列、旧 JSON 缺阶级或值非法时，必须补齐后才能应用；调试面板允许导入旧 JSON 并在“卡牌阶级”下拉中修复，不会静默归为初级。

## 6. 构建与运行门禁

- 构建前会执行配置门禁：检查编译清单是否存在、源工作簿摘要是否变化、生成资产是否缺失、Prefab 组件组合是否与配置一致。任何一项不通过都会抛出构建错误并终止构建。
- 同时检查 HUD 的 PanelSettings → Text Settings → 默认中文字体引用链，以及动态字体的源字体文件。缺失时执行 `Tools/Spotlight/生成中文字体资产` 后重新构建；TMP 卡牌能显示中文不代表 HUD 字体已正确绑定。
- 进入 Play 前同样执行门禁；不通过时阻止进入 Play 并提示执行 `Tools/Spotlight/验证配置` 或 `Tools/Spotlight/编译全部配置`。
- Windows / Android **非 Development** 构建不包含调试入口：三个调试脚本、面板骨架与两个入口按钮都不参与编译（不是隐藏），包内查不到 `ConfigDebugPanel` / `配置/调试` / `应用并重开`；请用该包完成一次完整对局作为发布前验收。
- 构建后会自动清理 Burst 调试信息：`Editor/BuildArtifactCleanup.cs`（`IPostprocessBuildWithReport`）删除输出目录下的 `*_BurstDebugInformation_DoNotShip` 与残留的 `lib_burst_generated.pdb`。菜单打包、命令行打包与 CI 打包都会走这条回调，不依赖 `BuildEntry`。
- 打包完成后用 `bash scripts/check-build-hygiene.sh` 复核：它递归扫描 `Build/` 的每个文件（含 `Build/windows/` 与 `Build/android/Spotlight.apk`），确认没有调试面板文案/类型名、`Spotlight.xlsx` 与 `_sourceWorkbook`/`_sourceHash`/`_compiledAtUtc`、以及 Burst 调试目录与符号文件。该脚本也作为 `repo-hygiene.yml` 的步骤运行（没有 `Build/` 时自动跳过，但自检步骤始终执行）。
- 该脚本是**硬门禁**：`Build/` 里任何文件（含 `Managed/*.dll`、`sharedassets*`、`globalgamemanagers.assets`）出现调试面板的类名或文案、工作簿路径/摘要、Burst 调试目录与符号文件，都会让检查失败。

## 7. 常见问题排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 提示“未找到配置资产，请先执行 Spotlight/编译全部配置…” | `Assets/Spotlight/Generated/Resources/SpotlightConfig.asset` 缺失或未编译 | 执行 `Tools/Spotlight/编译全部配置` |
| 进入 Play 被“配置门禁阻止进入 Play”拦下 | 配置从未编译、工作簿改后未重编译、生成资产缺失或被手工改动 | 按提示执行验证/编译；不要手工编辑 `Generated/` |
| 编译报“配置已过期” | 源工作簿摘要与清单不一致 | 重新执行 `Tools/Spotlight/编译全部配置` |
| 编译报“Deck 表已废除…” | 旧工作簿里还留着 `Deck` 工作表 | 删除该工作表；抽牌堆改在 `Rules` 的 `drawPileSize` + 三阶级比例里配 |
| 编译报“三阶级比例之和必须为 100”或“抽牌堆张数必须至少为 3” | 抽牌堆七个新列填得互相矛盾 | 按 [策划填写说明.md](策划填写说明.md) 第 3.2 节调数值 |
| 选卡面板里整行按钮都是灰的 | 该阶级已达有效上限（勾满）或该阶级没有任何可携带卡种 | 先取消其它卡种，或回到 Excel 给该阶级补一个 `tier` |
| 中文显示为方框或豆腐块 | 字体资产或 PanelSettings 未生成/未绑定 | 执行 `Tools/Spotlight/导入 TMP 基础资源` 与 `Tools/Spotlight/生成中文字体资产`，必要时重新执行 `Tools/Spotlight/生成演示场景` |
| 卡牌中文正常，顶部/日志/按钮只剩数字与英文 | HUD 的 PanelSettings 没有绑定 Text Settings；旧生成器把 Unity 2022.3 的公开字段误当成属性，静默漏绑 | 使用修复后的生成器执行 `Tools/Spotlight/生成中文字体资产`，确认 `SpotlightPanelSettings` 的 Text Settings 指向 `SpotlightTextSettings`，再重新打包 |
| 日志提示“HudView：未找到 UIDocument” | 场景缺少 UIDocument 或 UXML 未赋值 | 重新执行 `Tools/Spotlight/生成演示场景`，或手工把 `UI/Spotlight.uxml` 与 PanelSettings 绑定到 HUD 对象 |
| 日志提示“ConfigDebugPanel：界面缺少 debug-panel” | UXML 版本与代码不匹配 | 确认使用的是 `Assets/Spotlight/UI/Spotlight.uxml` 的最新版本 |
| 点击棋牌没有反应 | 处于弃牌阶段、模态面板打开、对局已结束或不是己方回合 | 看界面顶部中央的提示条（如“请先弃牌至手牌上限”“只有玩家回合可以使用手牌”）与对局日志 |
| 点击棋子无法选中（本回合内定位不到单位） | 卡牌挡住了格子的点击命中（已修复：棋盘卡牌关闭射线检测，只保留格子可点） | 确认使用的是最新运行时；`点击落点` 回归用例会验证射线命中到格子而非卡牌 |
| 日志说移动了但棋子还在原地 | 移动动画被中断后没有回到格心（已修复：渲染时校准位置、补间结束/被停止都把位移归零） | 直接在 Test Runner 跑 `Assets/Spotlight/Tests/PlayMode/` 下的回归用例确认 |
| 选中单位后没有高亮 | 单位本回合已行动、刚部署受召唤失调限制或维持费不足 | 查看单位详情里的行动机会说明 |
| 面板按钮点了没有变化 | 草稿校验未通过（名称重复、负数/小数移动距离、非法数量、无效卡种或升级目标） | 按状态区提示修正；“应用并重开”失败时原对局与草稿都会保留 |
| Excel 报错信息很多 | 校验会一次性汇总全部问题 | 按 `文件!表:行:列 原因` 从上到下逐条修复后重新验证 |

## 8. 测试与自检

- 规则、配置与棋盘视图契约测试位于 `Assets/Spotlight/Tests/EditMode/`，可在 Test Runner（EditMode）中运行，或用命令行：
  `-batchmode -runTests -projectPath <工程路径> -testPlatform EditMode -testResults <结果 xml> -logFile <日志>`。
- 棋盘交互与动效的端到端测试位于 `Assets/Spotlight/Tests/PlayMode/`：在真实帧循环里验证“移动后卡牌确实落在目标格”“连续回合中界面始终跟随规则快照”“点击棋子的射线落到格子上”。命令行把 `-testPlatform` 换成 `PlayMode` 即可（需要先执行 `Tools/Spotlight/编译全部配置`，否则配置门禁会阻止进入 Play）。
- GitHub Action（`.github/workflows/unity-tests.yml`）按**变更分层**决定跑哪套：文档层（`docs/**`、`*.md`、`AGENTS.md` 等）两套都跳过、只留大文件/LFS 检查；表现层（`Runtime/UI|View|Feedback`、uxml/uss/prefab、`Scenes/**`、`Tests/PlayMode/**`）只跑 PlayMode；规则层与交叉层两套都跑。判不准时一律两套都跑，需要强制全量时用 `workflow_dispatch` 手动触发。跳过的检查在 PR 上显示为灰色 **Skipped**（等同通过）。分层口径与理由见 [CI测试分层计划.md](tasks/completed/CI测试分层计划.md)。
- **触发时机：只在 PR 上跑，main 的 push 不重复跑。** `main` 由分支规则集「main」保护，且该规则集**只允许通过 PR 新增提交**：`pull_request` 规则要求所有变更都关联一个 PR，直推（包括普通快进推送）会被拒；`non_fast_forward` 另行禁掉强制推送，`deletion` 禁删分支，`bypass_actors` 为空（`current_user_can_bypass` 为 `never`，仓库所有者也不能绕过）。因此 PR 阶段被测的就是合并后落到 main 的结果，push 再跑一遍没有额外信息。需要临时在 main 上验证时，用 `workflow_dispatch` 手动触发。
- **合并门禁 = 三条必需检查全绿 + 分支不是 out of date，不需要任何人审阅。** 必需检查是 `EditMode 测试（Unity 2022.3.62f3）`、`PlayMode 测试（Unity 2022.3.62f3）`、`大文件与 LFS 一致性检查`，并开启了“要求分支最新”的严格模式；规则集不要求 approval（`required_approving_review_count` 为 0）、不要求 Code Owner 审阅，仓库也不使用 CODEOWNERS。三项全绿且分支已与 `main` 同步后，PR 作者即可自行手动合并；任一检查红灯或分支落后时 GitHub 会直接拦住合并。
- ⚠️ 规则集里的必需检查名是和 workflow 的 job 名**字符串精确匹配**的（如 `EditMode 测试（Unity 2022.3.62f3）`）。矩阵已拆成两个字面名 job，版本号直接写在 job 名里，改名或改 `unityVersion` 时要同步改规则集，否则 PR 会一直停在 pending。

### 8.1 仓库配置守卫脚本

四个秒级、不依赖 Unity 的守卫脚本，本地可跑，也作为 `repo-hygiene.yml` 的步骤在每次 PR 上执行：

```bash
bash scripts/check-repo-hygiene.sh            # 大文件与 LFS 一致性
bash scripts/check-repo-hygiene.sh --self-test
bash scripts/check-ci-config.sh               # CI 触发配置（只允许 PR + 手动入口）
bash scripts/check-ci-config.sh --self-test
bash scripts/check-ci-config.sh --check-ruleset  # 另比对本机 gh 能读到的分支规则集
bash scripts/classify-change-set.sh --self-test  # 变更分类器的分层用例
bash scripts/classify-change-set.sh --files <清单>   # 本地模拟：看看这份变更会跑哪套
bash scripts/check-build-hygiene.sh           # 发布包体去调试化（需先打过包；无 Build/ 时跳过）
bash scripts/check-build-hygiene.sh --self-test
```

- `check-repo-hygiene.sh`：拦截未走 LFS 的大二进制（阈值用 `MAX_FILE_MB` 调整，默认 5）。
- `check-ci-config.sh`：保证各 workflow 不含 `push` 触发、且保留 `pull_request` 与 `workflow_dispatch`；
  并校验 `unity-tests.yml` 的三条结构约束：①两套 Unity 串行（`playmode-tests` 的 `needs` 必须包含 `editmode-tests`，
  矩阵拆开后不能再靠 `max-parallel: 1`）；②不得使用 workflow 级 `paths`/`paths-ignore`（否则必需检查永久 Pending、PR 被锁死）；
  ③分类接线完整（调用 `scripts/classify-change-set.sh`、两个测试 job 都 `needs` 分类 job、`if` 带 `always()` 与分类失败兜底）。
  同时校验**顶层 `concurrency` 必须是仓库级固定组名 `unity-seat`**（不能含 `github.ref` 之类变量、不得 `cancel-in-progress: true`）：
  按 ref 分组会让两个 PR（`refs/pull/N/merge` 各不相同）同时启动，各自 `--activate-all` 抢同一个个人版席位，
  输的一方拿到 `0 free entitlements` 整轮假失败；中途取消正在运行的 Unity 又会泄漏席位。
  如果将来放宽了 main 的分支规则（允许直推/绕过检查/关闭“要求分支最新”），就需要把 `push` 触发加回来，并同步调整这个守卫。
- `classify-change-set.sh`：把 PR 的变更文件分成文档/表现/规则/交叉四层，输出 `edit` 与 `play` 两个开关，
  供 `unity-tests.yml` 决定两个测试 job 是否执行。规则表在脚本顶部的 `_file_layer`，新增目录时改那里并补 `--self-test` 用例；
  它算错只会表现为“少跑一层测试”，所以每次 PR 都跑自检。
- `--check-ruleset`：把各 workflow 会产生的 job 名（含矩阵展开）与规则集里声明的必需检查名对比，并确认规则集没有重新要求人工审阅（approval / Code Owner 审阅 / required_reviewers）。
  注意它只校验“规则集要求的名字在 workflow 里存在”这一个方向，**不校验反向**：某条 workflow job 忘了被设为必需检查（例如曾经漏配 `PlayMode 测试（Unity 2022.3.62f3）`）它不会报错，改规则集后需人工核对必需检查清单。
  需要本机 `gh` 已登录且有 admin 权限，**只能在本地跑**（GitHub Actions 默认的 `GITHUB_TOKEN` 读不到规则集）。
  它拦截的是一个从日志里完全看不出、也没有超时的故障：**job 名里嵌了 `${{ matrix.unityVersion }}`，
  所以只改 CI 的 Unity 版本就会让所有 PR 永久停在 pending**。合并前建议先跑一次。
- 修改规则、公开接口、配置字段或工具操作后，需要同步更新本文与 [策划填写说明.md](策划填写说明.md)，并按 [最初版本实现方案.md](最初版本实现方案.md) 第 5 节补充回归用例。
- `check-build-hygiene.sh`：扫描 Windows / Android 构建产物，确认没有开发期信息（调试面板文案/类型名、`Spotlight.xlsx`、`_sourceWorkbook`/`_sourceHash`/`_compiledAtUtc`、Burst 调试目录与符号文件）。默认递归扫 `Build/`（`Build/windows/` 与 `Build/android/` 都覆盖），目录不存在时判定为“没有产物可查”并退出 0。
  它拦的是**拆包才看得见**的问题：这类泄露不会让游戏崩、也不会让测试红，只能靠字符串扫描。注意 `lib_burst_generated.dll` 与托管程序集里的普通 `.pdb` 字样属于正常内容，不要用宽泛的 `grep pdb` 做门禁。

### 8.2 发布 Windows / Android 包（当前为手动流程）

CI 自动打包**尚未接入**：曾经用 `game-ci/unity-builder` + `schedule` 做过夜间发版，已整体移除（见 PR #29）。
原因是 `unity-builder` 的前置校验只认 `UNITY_LICENSE`(.ulf) 或 `UNITY_SERIAL`，不接受个人版的“邮箱+密码认领席位”——
两次实测都在步骤启动后 0.3 秒报 `Missing Unity License File and no Serial was found`（未下载 CLI、未起容器），
而 .ulf 对 Personal 是机器绑定的、serial 需付费订阅。恢复自动打包需要换到带 `cliVersion` 的 builder（v5.0.1 / v6.0.0）
并在分支上先手动 dispatch 验证，确认能出包后再重新引入触发与发布步骤。

在那之前，发版走下面几步。两个平台的产物分目录存放，每个子目录都是一份可直接压缩交付的完整包：

| 平台 | 菜单 | 产物 |
|---|---|---|
| Windows | `Tools/Spotlight/打包 Windows 版本` | `Build/windows/`（`Spotlight.exe` + `Spotlight_Data/` + `UnityPlayer.dll` + `MonoBleedingEdge/`） |
| Android | `Tools/Spotlight/打包 Android 版本` | `Build/android/Spotlight.apk`（单文件，调试签名，可直接侧载） |
| 两者 | `Tools/Spotlight/打包全部版本（Windows + Android）` | 上面两份产物 |

命令行（CI/脚本用同一入口，方法与菜单一一对应）：

```bash
Unity.exe -batchmode -nographics -quit -projectPath <工程根> \
  -executeMethod Spotlight.EditorTools.BuildEntry.BuildAll -logFile <日志路径>
# 单平台：BuildWindows / BuildAndroid
```

打包行为要点：

1. 每次打包只清空**该平台自己的**子目录（`Build/windows/` 或 `Build/android/`），不会连带删掉另一个平台的包；
   历史遗留的 `Build/` 根目录旧产物请手动删除。
2. Android 构建期会临时覆盖三项设置并在构建后还原：出 **APK**（不是 AAB，AAB 不能直接 `adb install`）、
   **ARMv7 + ARM64** 双 ABI（默认工程只勾 ARMv7，纯 64 位机型会装不上）、**仅横屏**
   （棋盘 10 列宽、CanvasScaler 按 1920×1080 设计，竖屏装不下）。
3. Android 的脚本后端在 `ProjectSettings` 里**固定为 IL2CPP**：Mono 后端不支持 ARM64，即使勾了 ARM64 也会被静默降级成
   纯 armeabi-v7a 的包；改回 Mono 会导致新机型装不上，不要改。
4. 复核产物：`bash scripts/check-build-hygiene.sh` 必须通过（它递归扫描 `Build/` 下两个平台的全部文件，
   同时确认 Burst 调试目录已被 `BuildArtifactCleanup` 删干净）。
5. 压缩成 zip：整目录打包即可，`*_BurstDebugInformation_DoNotShip` 已由构建回调删除；保险起见仍可加排除参数
   （`7z a -tzip -mx=5 ..\spotlight2026-windows-v0.0.1.zip . -xr!*_DoNotShip`，在 `Build/windows/` 下执行；
   Android 直接传 `Build/android/Spotlight.apk` 即可）。
6. 真机验收：Windows 双击 `Spotlight.exe`；Android 用 `adb install -r Build/android/Spotlight.apk`，
   两侧都应直接进入「携带选择」面板。
7. 发布（tag 用版本号，不要占用将来 CI 的 `nightly`）：
   `gh release create v0.0.1 <windows.zip> <Spotlight.apk> --title v0.0.1 --notes "<构建信息>"`
   已存在则 `gh release upload <tag> <文件...> --clobber`。
8. 验证：`gh release view <tag>`、`gh release download <tag> -D ./dl`；撤销用
   `gh release delete <tag> --cleanup-tag --yes`。

注意：Release 资产不进 git，与 LFS 规则无关；单资产上限 2 GB。包里的 exe 必须和同目录数据文件一起解压才能运行。
APK 使用 Unity 调试签名，适合内部试玩，不能直接上架应用商店。

## 9. Boss 延迟十字炸弹配置与操作

1. 编辑 `Assets/Spotlight/Config/Spotlight.xlsx` 的 Rules 表炸弹三列：`bossBombInterval`（部署间隔，默认 10）、`bossBombDamage`（总伤害，默认 3）、`bossBombColumn`（显示列号，默认 5）。均须填写至少 1 的整数；旧工作簿必须补齐这三列，不使用公式。
2. 执行 `Tools/Spotlight/验证配置`，通过后执行 `Tools/Spotlight/编译全部配置`。不要手改 Generated 资产。旧调试 JSON 缺少这些字段时会显示校验错误，补齐后才能应用。
3. 第 10、20、30……回合玩家行动前，AI 自动随机选行部署炸弹。手动模式须先点击“布置炸弹”后选择高亮格，或点击“跳过炸弹”；处理后再开始玩家普通操作。普通放牌次数不受影响，两种先手使用相同时机。
4. 炸弹在下一完整回合玩家行动前自动爆炸，早于资源产出、维持费与抽牌；间隔为 1 时先爆旧炸弹再部署新炸弹。棋盘角标与日志显示部署位置、到期回合和伤害。列号始终从屏幕左侧算起，最多取棋盘列数的一半向下取整。
5. 技能及普通行动按阶段展示：部署和爆炸各自显示发生时的玩家回合号，技能反馈结束后才开放本回合玩家操作。期间不能出牌、移动、攻击或结束回合；可重开取消旧反馈。打开配置面板不会提前显示下一阶段，关闭后继续展示。
5. 调试面板 Boss 分区支持修改这三个参数，仅对“应用并重开”的新对局生效。表现层沿用 `Presentation.feedbackSeconds` 控制单格闪光时长，`attackTargetColor` 控制颜色；外部可通过 `CardFeedback.Configure`、`PlayBombDeploy`、`PlayBombExplosion` 接入表现，不参与规则结算。
6. 新增回归位于 `BossBombTests`（EditMode）与 `BossBombPlayModeTests`（PlayMode），覆盖部署/引爆时序、共享预算、手动权限、镜像列号、点击穿透、动画与重开清理。

## Boss 刷怪卡配置与操作

1. Rules 表的 `bossSpawnerAttackThreshold`、`bossSpawnerCountFromColumn`、`bossSpawnerUnitThreshold`、`bossSpawnerDeployFromColumn` 默认分别为 12、4、2、5。全部为正整数，两个列号从玩家一侧第 1 列起算，包含本列，超过棋盘宽度则范围为空。表头批注有详细中文说明。
2. `bossSpawnerCardType` 默认引用 Cards 的 `bossSpawner`，该行 `hp` 是可配置生命，默认 1；该 Cards 行启用 `spawnComponent`，`spawnCardType` 默认引用已有的 `bossCombat`。刷怪卡阶级为 `none`，不会出现在携带选择里，也不会进入玩家抽牌堆。修改后执行“验证配置”及“编译全部配置”，不要手改生成资产。
3. 一阶段每个 Boss 回合开始，玩家单位总攻击力与前线攻击类单位数量同时达标且没有刷怪卡时，AI 随机部署；手动模式点击“部署刷怪卡”选择高亮空格，或点击“跳过刷怪卡”。处理完技能才能普通行动，普通放牌次数不扣除。
4. 刷怪卡固定不动，默认 1 血，可被攻击；下一次 Boss 回合开始起每回合在周围八格生成一架战机。空格优先，无空格时随机顶替玩家单位；家和 Boss 单位不可顶替。没有可用位置则暂停，有空位后自动恢复，战机遵守召唤失调。
5. 调试面板 Boss 分区可修改技能阈值、列号、卡种引用和刷怪卡生命，只在成功“应用并重开”后对本次运行生效。旧 JSON 缺少新字段会显示明确错误，原对局不会被替换。
6. 日志显示技能机会、据点生命、生成及暂停原因；选中刷怪卡时右侧卡面详情显示它的刷怪与不可行动规则。重开会清理机会、刷怪卡、战机和旧动画。测试位于 `BossSpawnerTests`、`BossSpawnerConfigTests` 和 `BossSpawnerPlayModeTests`，随既有 PR 工作流运行。

## Boss 阶段参数、战舰与配置迁移

正式默认 Boss 生命为 **30**（Homes 的 boss 行）。Rules 新增：

| 字段 | 默认值 | 约束 |
|---|---|---|
| `bossPhaseTwoHp` | 20 | 正整数且小于 Boss 初始生命 |
| `bossWarshipColumn` | 8 | 玩家一侧起算，必须位于棋盘列范围内 |
| `bossWarshipCardType` | bossWarship | 引用具有刷怪能力、可移动/攻击/互换且不能攻击资源单位的攻击卡 |

Cards 的 `bossWarship` 默认 hp=15、atk=2、range=1、moveDistance=1、spawnComponent=true、spawnCardType=bossCombat、canAttackResources=false、canSwap=true。普通刷怪笼保持稳定 ID `bossSpawner`、生命 1，启用同样的刷怪能力，canSwap=false。正式卡组不加入战舰或刷怪笼。

旧 Excel / JSON 必须显式迁移，不能直接使用旧全局字段：

1. 将旧 Rules 的 `bossSpawnerSpawnCardType` 值移到原刷怪笼 Cards 行的 `spawnCardType`，该行 `spawnComponent=true`，然后删除旧 Rules 字段。
2. 所有 Cards 行补齐 `spawnComponent`、`spawnCardType`、`canAttackResources`、`canSwap` 列/字段。普通卡前两者为 false/空串，后两者为 true；普通刷怪笼 canSwap=false；战舰使用上面的配置。
3. 添加战舰 Cards 行与 Rules 的三个阶段字段，保证阈值小于 Homes 的 Boss 生命。不要覆盖已有玩家卡数值。
4. Excel 执行“验证配置”→“编译全部配置”，编译器保留已有资产 GUID，生成 `<id>_Spawn` 子资产及对应 Prefab 组件。JSON 只修改本局草稿；验证失败不能应用重开。

战斗界面顶部的常驻摘要提示二阶段锁血与战舰待部署、存活、已击败数量。二、三阶段隐藏一阶段技能按钮，手动普通放牌及“跳过放牌并结束”继续可用。两舰击败立即解锁，三阶段技能本次为空。

调试面板 Boss 分区可修改阈值、战舰列、战舰引用及属性；每卡支持刷怪开关、生成卡种和战斗权限。“应用并重开”成功后清空阶段记录、单位与旧表现队列，失败保留原对局及面板。定位与回归入口见 `BossPhaseStateMachine.cs`、`GameSession.BossPhases.cs`、`SpawnResolver.cs`、`BossPhaseTests`、`BossPhaseConfigTests`、`BossPhasePlayModeTests`。


## 三阶段护卫舰配置与迁移

现有工作簿仍为五张表。Cards 新增 Boss 专用攻击卡 `bossGuardType1`（一式护卫舰，7/1/2/1）和 `bossGuardType2`（二式护卫舰，3/3/2/1），数值顺序为生命/攻击/射程/移动距离，均为 `tier=none`、允许攻击资源、允许互换、无维持费。Rules 必须增加 `bossPhaseThreeFrontCardType` 与 `bossPhaseThreeRearCardType`，分别引用这两行。引用不能指向玩家可携带卡、即时卡或治疗型卡；生命、攻击和射程须为正整数，移动可为 0。

旧工作簿或调试 JSON 必须显式补齐两项引用，不静默采用固定卡名。迁移时保留原有数值，执行“验证配置”及“编译全部配置”更新只读生成资产。调试面板 Boss 区新增“三阶段护卫舰”，可调整引用与属性；修改仅在“应用并重开”后作用于本次会话，不写回 Excel 或正式资产。

击败二阶段两艘指定战舰后即生成两列护卫舰，默认共 9 艘。索敌顺序为攻击类单位、玩家家、特殊单位、资源单位；攻击类优先距 Boss 家最近、同距攻击力最大。强制顶替按死亡结算，区别于通用刷怪顶替；双方的家与已有炸弹保留。
