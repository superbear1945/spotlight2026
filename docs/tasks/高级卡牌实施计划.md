### 1.2 后羿-II：四邻空格限制

1. 上下左右四个方向中，至少 2 格为空；斜角不计。
2. 棋盘外按空格计算。棋盘内双方战斗单位和双方的家均算占用；炸弹地面标记不占格。
3. 部署时检查目标格。
4. 移动时同时检查两个布局：移动前的当前位置、移动后的目标位置。两者都必须满足条件。
5. 目标位置按原格已经腾空、新格已经占用的最终布局计算。
6. 只检查起点和落点；路径中间格不检查空格数量。路径仍遵守普通四向寻路、占位和移动距离。
7. 互换也检查交换前、交换后的布局，且检查双方中所有具有该能力的单位，不论其是发起方还是目标。
8. 其它单位可以靠近，将它围到不足 2 个空邻格；不因此撤销那些单位的移动或部署。
9. 被围后仍可攻击；移动和互换被禁止，直到当前位置重新满足条件。
10. 该限制不阻止普通回合恢复，不改变攻击射程、召唤失调、维持费和离场规则。

### 1.3 维京长船：击杀恢复行动

1. 该单位的一次直接攻击使目标战斗单位死亡后，恢复一次普通行动机会。
2. 本次攻击触发的伤害标记追加伤害击杀目标，也归属于本次攻击，满足触发条件。
3. 恢复后可正常移动、攻击或互换；主动离场继续沿用既有规则。
4. 恢复后再次攻击击杀，可再次恢复；不设置每回合触发次数上限。
5. 未使用的机会不累计，不跨回合保存。
6. “和进入新回合一样”在这里指该单位可再次正常行动，不实际调用 `BeginTurn`：不抽牌、不产资源、不重复扣维持费、不恢复其它单位、不增加出牌次数、不恢复生命、不重置其它能力进度。
7. 恢复机会后执行移动或互换，照常消耗该机会；互换的另一方不因维京长船的能力获得额外机会。
8. 其它单位击杀、炸弹击杀和离场等移除不会让维京长船恢复行动。家被摧毁按胜负结算结束，不开放后续操作。

### 1.4 SNP-EU：伤害标记

1. 只有具有该能力的单位直接攻击战斗单位，才能施加标记；家不能被施加标记。
2. 一次攻击完成后，存活目标增加 1 层。首次攻击无既有标记时只结算本次攻击力。
3. 同一来源、多来源都可叠层；不设置玩法层数上限。
4. 本次受伤按受伤前已有标记结算，新挂的层从下一次受伤起生效。
5. 标记永久保留到被标记单位离场；标记者离场、跨回合、移动、互换和治疗均不移除标记。
6. 普通攻击、炸弹等直接伤害均可触发已有标记。治疗、离场、覆盖升级、战机顶替不是伤害，不触发。
7. 正式默认值：每层在一次直接伤害后追加一次 1 点伤害。追加伤害本身既不再次触发标记，也不施加新标记。
8. 追加伤害沿用当前直接伤害的归属：后续由维京长船攻击，则追加伤害归维京长船；由其它单位攻击则归该单位；由炸弹触发则归该炸弹技能，不归最初的 SNP-EU。
9. 目标死亡即终止对它的后续扣血，不对已移除对象继续追加，不产生重复死亡事件。
10. 来源卡牌重新部署产生新单位，既有受伤标记不会反向写入卡牌记录、卡种配置或其它同种单位。

### 1.5 炸弹与伤害标记的明确交互

- 现有炸弹对一个单位逐点扣除基础伤害；每一笔基础 1 点伤害独立触发已有标记。
- 追加伤害不扣炸弹预算，只有基础扣血扣预算。
- 追加伤害提前击杀后，剩余基础预算按既有搜索顺序继续寻找其它目标，不在该格浪费预算。
- 例如：10 血、2 层标记、3 点基础预算，连续三轮分别为 `1 基础 + 1 追加 + 1 追加`，总计 9 点，剩余 1 血。
- 例如：4 血、2 层标记、3 点基础预算，第一轮变 1 血；第二轮基础伤害击杀，不再追加，仍有 1 点基础预算供后续搜索。
- 炸弹仍只伤害玩家战斗单位，不因此修改搜索方向、忽略双方家和 Boss 单位等既有规则。

### 2.1 组件边界

本方案新增 **3 组能力配置组件**，每组包含 Core 接口、不可变数值实现和 Runtime SO；不新增 MonoBehaviour。

| 能力 | Core 接口 | 文档配置数值实现 | Runtime SO | 生成子资产后缀 |
|---|---|---|---|---|
| 四邻空格限制 | `IAdjacentClearanceConfig` | `AdjacentClearanceValues` | `AdjacentClearanceConfigSO` | `_AdjacentClearance` |
| 击杀恢复行动 | `IKillActionConfig` | `KillActionValues` | `KillActionConfigSO` | `_KillAction` |
| 伤害标记 | `IDamageMarkConfig` | `DamageMarkValues` | `DamageMarkConfigSO` | `_DamageMark` |

- 四邻空格配置公开 `MinEmptyNeighbors`。
- 击杀恢复行动是开关型能力：以非空配置表示启用，不引入“回合上限”“累计次数”等未要求参数。接口可作为能力标识，SO 不重复序列化启用布尔值。
- 伤害标记配置公开 `DamagePerStack`；一次直接攻击新增一层是机制语义，每层追加伤害数值来自配置。正式表填 1。
- `CardArchetype` 增加 `AdjacentClearance`、`KillAction`、`DamageMark` 三个只读属性。
- Prefab 沿用 `Card + CombatComponent + ResourceComponent`；不为五种卡建立子类。
- `Card.cs`、`ViewTemplateBuilder`、`.asmdef` 不因这些纯规则能力增加依赖或组件引用；外观需要时由现有视图读取快照和定义。
- 所有新类、方法必须详细注释职责、输入输出与存在原因；私有字段使用 `_` 前缀。

## 4. 四邻空格限制的规则内核设计

修改 `Core/GameSession.cs`，新增以下职责明确的辅助方法（名称可在编码时保持同义一致）：

| 方法 | 输入 | 输出／职责 |
|---|---|---|
| `CountEmptyOrthogonalNeighbors` | 中心格、占位查询 | 返回 0～4；四个方向必须完整枚举，棋盘外直接计空 |
| `ClearanceError` | 卡种／单位、位置、占位查询 | 无该能力返回 null；否则返回条件不足原因 |
| `MovementError` | 单位、目标格、已求得路径 | 共用行动资格、普通路径、起点与落点条件 |
| `SwapError` | 互换双方 | 共用互换资格、前后布局和双方能力检查 |

### 4.1 模拟最终布局，不提前修改状态

- 普通移动的占位查询覆盖旧位置与新位置：旧格空、新格由移动者占用，其它格照常。
- 互换不能把两个原位置都当空：最终两个格仍各有一个单位；只改变哪个单位位于哪个格。
- 家继续算占位；炸弹不算占位；越界邻格按空处理，但单位落点自身仍必须在棋盘内。
- 不通过“先修改位置、校验失败再改回”的方式试算，避免失败命令污染状态或触发标记。
- 起点条件在原布局检查，终点条件在最终布局检查；只检查本次移动／互换涉及的能力单位。

### 4.2 接入位置

1. `DeploymentError` 增加目标格空格检查；正常区域和星门扩展校验继续生效。
2. `Move` 在任何写状态前调用共用移动检查；成功才写位置、消耗行动和调用 `RefreshMarking`。
3. `GetLegalActions` 的 `Move` 与 `Swap` 使用同一组检查，确保高亮和真实命令一致。
4. `Swap` 校验双方之后才同时写入两者位置和行动状态。
5. 普通 `Paths` 继续生成可通行路径，不拿空格限制过滤中间节点，否则会错误禁止经过临时狭窄格。
6. `RunBoss` 的移动候选、实际截断落点都检查条件。远处攻击位置合法不代表本回合走到的中间落点合法；需要从本回合可达且合法的落点中选取。
7. `CanAttack` 与 `Available` 不加入空格限制，避免被围时攻击也被禁用。
8. 保持其它单位靠近合法；不得引入全棋盘“所有能力单位必须始终满足”的校验。

## 5. 统一伤害结算与伤害归属

这是本次优先实施的公共基础；必须先保证普通攻击与炸弹不挂标记时保持原行为，再接入新效果。

### 5.1 新增数据契约

建议新增 `Assets/Spotlight/Core/DamageResolution.cs`，只使用纯 C#：

| 类型 | 关键数据 | 用途 |
|---|---|---|
| `DamageKind` | 普通攻击、炸弹、标记追加 | 区分直接伤害与追加伤害，禁止递归 |
| `DamageContext` | 来源阵营、来源单位 ID（可空）、目标单位 ID、伤害类型、根伤害类型、炸弹信息（可空） | 追加继承根来源；炸弹不伪装成某个 SNP-EU |
| `DamageResult` | 实际扣血、目标是否死亡、目标 ID、来源、基础与追加结果 | 攻击分支、击杀恢复和表现读取事实，不凭结果快照猜归属 |
| `DamageMarkLayer` | 施加时复制的每层伤害值 | 保存永久标记数值，来源离场不失效 |

设计要求：

- `GameEvent` 增加可选结构化伤害结果，旧构造调用通过末尾可选参数保持兼容。
- `SubjectId` 仍可指被击中的目标，来源单独记录，不为适配旧动画而混用源与目标身份。
- 不新增从 UI 提交伤害的公开命令；伤害入口是规则层内部结算步骤。
- 若伤害结果包含集合，复制为独立只读数据；日志、命令结果和旧快照不能持有可变内部集合。

### 5.2 UnitState 新状态

在 `Core/GameState.cs` 增加永久伤害标记数据：

- 每个目标持有独立的标记层集合，每层保存施加时的配置伤害副本。
- 对外暴露层数和每次直接受伤的预期追加总量，供详情显示；不暴露可写集合。
- `UnitState.Copy()` 不能继续仅靠浅拷贝共享可变层集合；必须复制集合或使用真正不可变、变更时替换的表示。
- 支持不同调试配置来源施加的层拥有不同伤害值，不在触发时回读当前在场 SNP-EU 配置。
- `Place` 初始化为空；单位死亡、离场、升级、被顶替后随单位移除。重新部署不继承。
- 无需在目标上保存最初 SNP-EU 的击杀归属；追加伤害归属于触发本次受伤的根来源。
- 层数和总伤害计算须避免整数回绕；累计计算使用宽类型，实际扣血不超过剩余生命。不引入任意玩法层数上限。

### 5.3 内部结算步骤

新增 `ResolveDirectDamage` 与只扣一次生命的底层方法；底层方法不再触发任何伤害标记。

一次直接伤害：

1. 接收目标、当前基础伤害值和根来源；不从动画、日志或基础卡种重新计算本次攻击力。
2. 固定本次受伤前已有标记层，避免新增层提前生效。
3. 扣基础生命并记录实际伤害；归零则调用一次 `Remove(..., Death)` 并结束。
4. 仍存活时，按已有层依次追加配置伤害，每一笔沿用根来源并标记为追加类型。
5. 任一步归零即结束，不继续访问已移除单位；死亡加攻、标记奖励和兵位计时只处理一次。
6. 返回整个直接伤害及其追加是否造成目标死亡，供攻击者判断击杀恢复。
7. 只有直接攻击分支在这一整组伤害结束后，对仍存活的战斗单位施加一层新标记；治疗与炸弹绝不施加层。

普通攻击仍按“当前攻击力”一次结算基础伤害，不拆成攻击力次 1 点，否则会错误多次触发标记。

### 5.4 攻击分支调整

`CommandKind.Attack` 保留目标、射程和行动资格复验，然后：

1. 先将攻击者 `Acted=true`，消耗本次普通行动。
2. 治疗分支沿用既有治疗逻辑，既不触发伤害标记，也不施加标记或恢复行动。
3. 对战斗单位调用统一直接伤害入口；对家沿用伤害扣血和胜负检查，家不具备伤害标记。
4. 目标存活且攻击者具有 `DamageMark` 时，增加一个配置值副本层，发出 `damage-mark` 事件。
5. 目标因整组攻击伤害死亡，且攻击者仍在场、具有 `KillAction` 时，仅恢复该攻击者 `Acted=false`，发出 `action-restored` 事件。
6. 检查胜负；结束对局后不允许新命令或 AI 继续行动。
7. 不通过扫描“这次命令发生过任何死亡”恢复行动，要使用该次根攻击的结果，避免认错死亡来源。

### 5.5 炸弹分支调整

修改 `ResolveBombCell`：

- 每轮先消耗 1 点基础预算，再对该目标调用基础伤害为 1 的统一入口。
- 标记追加不改 `remaining`；目标死亡后结束该格循环，继续原搜索。
- 炸弹上下文保存 Boss 阵营和炸弹身份信息，来源单位为空，不记录为标记施加者。
- 该路径不调用攻击后施加标记／恢复行动步骤。

修改 `BombBlastStep`：

- 保留现有 `Damage` 的预算消耗语义，新增 `BonusDamage` 与 `TotalDamage`，避免旧逻辑把总伤害当预算。
- `Killed` 来自实际结算结果；步骤是独立只读对象。
- 爆炸事件中的预算消耗与造成的总扣血分开记录；原先用 `bomb.Damage - remaining` 得到的是预算消耗，不能再标成全部实际伤害。
- `GameBootstrap` 和 `CardFeedback` 只播放已生成的结果，不能自行重跑追加伤害。

## 6. 击杀连续行动与 AI

### 6.1 保留当前行动模型

`Acted` 已足够表达本需求：每次普通操作最多消耗一次机会，击杀后恢复为可行动。无需累加行动点，也不新增跨回合待领取奖励。

- `CanAct` 继续检查维持费支付和刷怪卡限制。
- `BeginTurn` 继续统一恢复各单位，未使用恢复机会自然不会跨回合叠加。
- 只改 `Acted`，不重置死亡加攻触发次数、部署减攻、伤害标记等本局状态。
- 高亮应在每次命令后根据新快照重算；连杀后出现下一批合法移动／攻击／互换目标。

### 6.2 RunBoss 调整

即使正式默认 Boss 暂不使用新卡，也须保证配置引用新能力时规则一致：

1. 保留按部署顺序遍历单位的外层顺序。
2. 每个单位内部按最新状态循环决策：可行动时优先合法攻击，否则按现有策略移动或待机。
3. 只有攻击击杀恢复后才进入下一次决策；非击杀攻击、移动、待机或对局结束均终止该单位本回合循环。
4. 每次重新查询目标、占位、路径和死亡加攻后的当前攻击，不缓存上一次结果。
5. `AttackPriority` 的可击杀判断使用与规则一致的无副作用伤害预测，包含目标既有标记；预测不能挂新层、扣生命或触发奖励。
6. 不添加随意的连杀次数上限。结束性由实际击杀减少有限目标、或操作消耗行动保证；命令失败必须退出当前循环，避免卡死。
7. 保留 AI 当前不主动互换的策略；能力只让它有机会继续正常决策。

## 11. 实施顺序与 PR 建议

每一步同时提交对应测试，避免先改结算、后补测试。

### PR 1：伤害结算基础

- 新增伤害上下文、结构化结果；普通攻击与炸弹迁移到统一扣血入口。
- 保持无标记行为，支持实际伤害和预算分开记录；补伤害归属、单次死亡、原有联动回归。
- 这一 PR 不暴露半成品新卡，保持正式配置可用。

### PR 2：伤害标记完整链路

- 新增标记接口、SO、字段、状态、施加时序、逐点炸弹追加与事件。
- 打通表结构、所有现有行的新列默认值、SO 往返、调试配置和详情。
- 用测试夹具验证 SNP-EU机制及与维京式能力的根来源接口；正式卡清单可留待最终数据 PR。

### PR 3：四邻空格与击杀恢复

- 加入另两种能力完整配置链路，修改移动与互换最终布局、恢复行动、AI 再决策。
- 测试恢复后普通操作、连杀、围堵、路径与互换双方约束。
- 所有正式 Excel 新列都同步补齐，不能让中间 PR 因缺表头过不了配置门禁。

### PR 4：五张正式卡与交付验证

- 正式工作簿和默认生成器增加五卡，更新高级池与字体、文档。
- 通过既有编译流程生成资产；不手改 Generated。
- 提交真实帧循环的点击、拖放、连续行动和炸弹反馈测试。
- 校正卡种计数和默认选卡契约；验证五种新卡可选、可部署、可结算。

也可把上述阶段放进一个功能 PR，以阶段提交组织；无论如何，合并的每个 PR 都必须配置完整、可加载，不提交缺新列的正式工作簿。
