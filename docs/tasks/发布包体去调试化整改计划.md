## 3. 问题清单（按优先级）

### P0-1 `*_BurstDebugInformation_DoNotShip/` 会泄露构建机绝对路径

**证据**（旧包 `Build/2026spotligt_BurstDebugInformation_DoNotShip/Data/Plugins/x86_64/lib_burst_generated.txt`）：

```
--temp-folder=D:\Unity\Project\spotlight2026\Temp\Burst
--decode-folder=D:\Unity\Project\spotlight2026\Library\Burst
--key-folder=D:/Unity/Editor/2022.3.62f3/Data/PlaybackEngines/WindowsStandaloneSupport
--linker-options=PdbAltPath="2026spotligt_Data/Plugins/x86_64/lib_burst_generated.pdb"
--method=Unity.Jobs.IJobForExtensions+ForJobStruct`1[[UnityEngine.Rendering.Universal.ZBinningJob, ...
```

Unity 自己在目录名里写了 `DoNotShip`。它不影响运行，纯粹是 Burst 编译记录。

**为什么这次重建没看到**：`BuildEntry.CleanOutputDirectory` 会先清 `Build/`，且 Burst 编译缓存已在
`Library/Burst` 里，本次没有重新生成。但 **CI 每次都是干净工作区**，`unity-tests.yml` 的打包步骤之后直接

```bash
cd build/StandaloneWindows64
zip -r "$GITHUB_WORKSPACE/spotlight2026-windows-nightly.zip" .
```

会把该目录一并打进 nightly 包（届时泄露的是 runner 的 `/github/workspace/...` 路径）。

> 版本变化（2026-10-18 抓取）：`origin/main` 已在 `f56bd49`「CI：整体移除夜间打包，workflow
> 回归纯 PR 测试」里删掉了 `build-windows` job，因此**合并 main 后 CI 面这条风险自动消失**；
> 本文基于本地分支 `superbear`（`d697d0a`）的 workflow，该分支仍含夜间打包步骤。
> 无论 CI 是否保留夜间打包，构建后清理 Burst 目录仍是本地打包与将来任何自动打包的必需步骤。
> 同理，下面对 `unity-tests.yml` 与 `check-ci-config.sh` 的改动在合并 main 后应改为
> “清理逻辑保留在 `BuildArtifactCleanup`，CI 步骤按合并后的 workflow 现状取舍”。

**修复**：

1. 新增 `Assets/Spotlight/Editor/BuildArtifactCleanup.cs`，实现 `IPostprocessBuildWithReport`，在
   `OnPostprocessBuild` 里删除 `<output>/*_BurstDebugInformation_DoNotShip`。
   - 必须用接口而不是只改 `BuildEntry`：CI 用的是 game-ci 内置构建脚本，不经过 `BuildEntry`。
   - 同时删除可能存在的 `lib_burst_generated.pdb`。
2. `.github/workflows/unity-tests.yml` 的“压缩构建产物”步骤前加一行兜底：
   `find build/StandaloneWindows64 -maxdepth 1 -name "*_BurstDebugInformation_DoNotShip" -exec rm -rf {} +`
3. `scripts/check-ci-config.sh` 增加静态校验：该 `rm -rf`/`find` 兜底存在，避免以后被人删掉。

**验收**：`find Build -name "*_BurstDebugInformation_DoNotShip"` 为空；nightly zip 解压后同样为空。

### P1-2 调试配置面板的代码与 UXML 骨架被打进发布包

**证据**（当前包）：

| 位置 | 命中内容 |
|---|---|
| `Managed/Spotlight.Runtime.dll` | `ConfigDebugPanel`、`DebugConfigDraft`、`ConfigFieldBuilder`、`DebugSupport` 类型名；中文提示（如 `ConfigDebugPanel：界面缺少 debug-panel`）；`_sourceHash` 字段名 |
| `globalgamemanagers.assets` | MonoScript 名 `ConfigDebugPanel` / `DebugConfigDraft` |
| `sharedassets0.assets` | 整段调试面板 UXML 树：`配置/调试` 按钮、`恢复默认`、`应用并重开`、`导出到下方`、`从下方导入`、多行 JSON `TextField` |

**运行期是否可被玩家触达：否**。三处闸门都在：

- `Runtime/Game/DebugSupport.cs:19` —— `IsDebugAvailable` 仅在 `UNITY_EDITOR || DEVELOPMENT_BUILD` 为真；
- `Runtime/Debug/ConfigDebugPanel.cs:92` —— 非调试构建里直接 `_panel.RemoveFromHierarchy()`；`:128` 的 `Open()` 也二次判定；
- `Runtime/UI/HudView.cs:180` —— 调试按钮 `style.display = None`。

**问题在于“拆包可见”**：任何用 AssetRipper / AssetsTools.NET 拆包的人都能直接看到“这游戏有一个可改棋盘、
卡表、Boss 参数并支持 JSON 导入导出的配置编辑器”。配置字段结构接近半张设计稿，属于不该给玩家的信息。

**与现有文档冲突**（需要一并修正）：

- `docs/使用说明.md:173`：“正式包（`BuildOptions.None`），不含调试配置面板”——不准确，实际是“面板不可达，代码与 UI 仍在包里”；
- `.github/workflows/unity-tests.yml` 里 Release Notes 的 “不含调试配置面板”；
- `Assets/Spotlight/Editor/BuildEntry.cs:100` 的注释。

**修复方案 A（推荐，彻底）**：

1. 用 `#if UNITY_EDITOR || DEVELOPMENT_BUILD` 包住三个文件的**全部内容**：
   `Runtime/Debug/ConfigDebugPanel.cs`、`ConfigFieldBuilder.cs`、`DebugConfigDraft.cs`；
2. `Runtime/Game/GameBootstrap.cs` 的 `[SerializeField] ConfigDebugPanel _debugPanel`（:40）、
   `OnDebugRequested`（:573）、以及 `HudView.DebugRequested` 的订阅（:164-165）同样条件编译；
3. 把 `UI/Spotlight.uxml:63`（`debug-button`）与 `:74-105`（`#debug-panel` 整块）拆到新文件
   `Assets/Spotlight/UI/DebugPanel.uxml`，由 `ConfigDebugPanel` 在调试构建里通过
   `VisualTreeAsset` 序列化引用加载（**不要放进 `Resources/`**，否则会被无条件打包）；
4. `Editor/SpotlightMenu.cs:144` 生成场景时添加 `ConfigDebugPanel` 与新的 UXML 引用；
5. 同步更新 EditMode/PlayMode 中引用调试面板的测试（用条件编译或改测 `DebugSupport.IsDebugAvailable`）。

**修复方案 B（低成本，先止血）**：保留代码，只把三处文档措辞改成“调试面板在正式包中不可达”，
承认可被拆包看到。适合时间紧、不希望动场景生成器的情况。

**验收**：发布包中 `grep -a "ConfigDebugPanel\|配置/调试\|应用并重开"` 在 `Build/**` 全部无命中。

4. 若暂时不想动契约，退一步：编译时就把三项写成空串（发布产物里没有任何路径信息）。

**验收**：`grep -a "Spotlight.xlsx" Build/**/sharedassets*.assets` 无命中，且构建门禁仍能在工作簿被改后拦截。

## 5. 防回归检查

本次调查用的扫描脚本（可直接扩成 `scripts/check-build-hygiene.sh` 或 CI 步骤）：

```python
import glob, os
needles = [
    "配置/调试", "应用并重开", "DebugConfigDraft", "ConfigDebugPanel",  # 调试面板
    "Spotlight.xlsx", "_sourceHash",                                    # 配置元数据
    "_BurstDebugInformation", "lib_burst_generated.pdb",                # Burst 调试信息
]
for path in sorted(glob.glob("Build/**/*", recursive=True)):
    if not os.path.isfile(path):
        continue
    data = open(path, "rb").read()
    hits = [n for n in needles if n.encode("utf-8") in data]
    if hits:
        print(path, hits)
```

配合一条目录断言：

```bash
! find Build -name "*_BurstDebugInformation_DoNotShip" | grep -q .
```

注意：`lib_burst_generated.dll` 与 `Managed/*.dll` 里的 `.pdb` 字样属于正常内容，**不要**用宽泛的
`grep pdb` 做门禁。
