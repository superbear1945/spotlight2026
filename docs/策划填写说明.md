# 策划填写说明：Spotlight.xlsx

本文面向策划，说明如何填写与维护正式数值来源 `Assets/Spotlight/Config/Spotlight.xlsx`。
规则本身以 [玩法.md](玩法.md) 为准；本文只描述“表格怎么填、工具怎么查错”。

## 1. 工作簿位置与基本流程

- 工作簿路径：`Assets/Spotlight/Config/Spotlight.xlsx`（Unity 工程根目录下的相对路径）。
- 固定 6 张工作表，名称必须完全一致：`Cards`、`Deck`、`Rules`、`Homes`、`BossSlots`、`Presentation`。多出或缺少任何一张表都会被拒绝。
- 推荐流程（Unity 菜单）：
  1. `Tools/Spotlight/生成默认工作簿`：按本文第 6 节的默认数值重新生成工作簿（已存在时会先确认覆盖）。
  2. 用 Excel 编辑数值；需要打开文件时可用 `Tools/Spotlight/打开默认工作簿`。
  3. `Tools/Spotlight/验证配置`：只校验，不写任何资产；全部通过时输出“验证通过：配置可用。”，有错时一次性列出全部问题并在末行给出问题总数。
  4. `Tools/Spotlight/编译全部配置`：校验通过后生成只读配置资产与每卡种 Prefab。
  5. 进入 Play 或构建前会再次检查源文件摘要、生成资产是否缺失、Prefab 组合是否与配置一致；不一致会阻止运行并提示重新编译。
- 生成产物位于 `Assets/Spotlight/Generated/`（卡种资产与 Prefab 在 `Generated/Cards/`，主配置在 `Generated/Resources/`）。**不要手工修改生成产物**：改动会在下一次编译被覆盖，并且会被运行/构建门禁判定为过期或篡改。

## 2. 通用填写规则

- 第 1 行是表头，列名必须与下表完全一致（大小写敏感）；第 2 行起是数据。
- 列顺序可以调整，工具按表头名取列；但**不能出现未声明的列**，也不能有“有数据但没有表头”的列。
- 整行留空的行会被跳过，方便在工作表末尾留空行；表中间的空行同样安全。
- 单元格留空视为该类型的默认值：文本 = 空串、整数 = 0、小数 = 0、布尔 = false。必需列留空会在业务校验里报错。
- 布尔列填写 `true` / `false`（不区分大小写），也接受 `1` / `0`；不要填写“是/否”或中文。
- 整数列不要写小数，小数列可以写 `0.5` 这样的值，小数点用 `.`。
- **正式数据单元格禁止公式**（包括共享公式）、禁止出现错误值（`#REF!` 等）、**禁止合并单元格**（第 1 行表头同样不允许合并）。
- 每张表的行数规则：`Cards` 至少 1 行；`Rules`、`Presentation` 恰好 1 行；`Homes` 恰好 2 行（player 与 boss 各一行）；`BossSlots` 恰好 3 行。
- 报错格式为 `文件!表:行:列 原因`，行号列号与 Excel 中看到的行列一致；报告按 文件 → 表 → 行 → 列 排序，便于逐条修复。

## 3. 各表列清单

### 3.1 `Cards`：卡种定义（每行一个卡种，每行生成一个 Prefab）

| 列名 | 类型 | 必需 | 取值与含义 |
|---|---|---|---|
| `id` | 文本 | 是 | 稳定 ID，全局唯一；字母开头，只允许字母、数字、`_`、`-`。改名不影响引用与升级关联 |
| `name` | 文本 | 是 | 展示名，非空；忽略首尾空格后不得与其他卡种重复 |
| `category` | 文本 | 是 | 只能是 `resource` / `attack` / `special` |
| `viewKey` | 文本 | 是 | 外观模板键，不能为空；改数值不会重建外观模板 |
| `hp` | 整数 | 是 | 初始生命与上限，必须 ≥ 1 |
| `atk` | 整数 | 否 | 攻击力，≥ 0；0 表示没有攻击能力 |
| `range` | 整数 | 否 | 曼哈顿攻击距离，≥ 0；0 表示不能攻击 |
| `moveDistance` | 整数 | 否 | 单次移动最大格数，≥ 0；0 表示不能移动，无玩法上的固定上限 |
| `produce` | 整数 | 否 | 每个己方回合产出，≥ 0 |
| `upkeep` | 整数 | 否 | 每个己方回合维持费，≥ 0 |
| `resourceComponent` | 布尔 | 否 | 是否启用资源组件；为 `false` 时 `produce`、`upkeep` 必须为 0 |
| `teleportComponent` | 布尔 | 否 | 是否启用传送组件；为 `false` 时 `permitsAttackDeploy` 必须为 `false` |
| `permitsAttackDeploy` | 布尔 | 否 | 是否允许己方攻击卡部署在其上下左右空格（星门用） |
| `deployHomeOnly` | 布尔 | 否 | 是否只能部署在己方边缘前两列 |
| `avoidAdjacentSameType` | 布尔 | 否 | 是否禁止部署在任何同卡种单位的四邻 |
| `requiresUpgrade` | 布尔 | 否 | 是否必须覆盖指定的己方资源单位才能部署；只有资源卡可以为 `true` |
| `upgradeFrom` | 文本 | 否 | 覆盖升级来源卡种 ID，必须指向**另一张资源卡**；`requiresUpgrade=false` 时必须留空 |

### 3.2 `Deck`：玩家初始卡组

| 列名 | 类型 | 必需 | 取值与含义 |
|---|---|---|---|
| `cardType` | 文本 | 是 | 必须引用 `Cards` 中存在的卡种 ID，且同一种卡只能出现一次 |
| `count` | 整数 | 是 | 初始张数，≥ 0；允许 0（只注册不上场） |

### 3.3 `Rules`：全局规则（恰好 1 行）

| 列名 | 类型 | 必需 | 取值与含义 |
|---|---|---|---|
| `rows` | 整数 | 是 | 棋盘行数，≥ 1 |
| `columns` | 整数 | 是 | 棋盘列数，≥ 2 |
| `homeRegionWidth` | 整数 | 是 | 己方区域宽度（列），必须在 1..`columns` 之间 |
| `playerPlays` | 整数 | 是 | 玩家每回合出牌次数上限，≥ 0 |
| `bossPlays` | 整数 | 是 | Boss 每回合放牌次数上限，≥ 0 |
| `drawCount` | 整数 | 是 | 玩家每回合抽牌数，≥ 0；0 表示不抽牌 |
| `handLimit` | 整数 | 是 | 手牌上限，≥ 0；结束回合超限必须先弃牌 |
| `initialResources` | 整数 | 是 | 初始资源，≥ 0 |
| `bossRespawnDelay` | 整数 | 是 | 兵位阵亡后的补兵间隔（完整回合数），≥ 1 |
| `playerSide` | 文本 | 是 | 玩家所在边缘，只能是 `left` / `right` |
| `firstSide` | 文本 | 是 | 先手方，只能是 `player` / `boss` |
| `bossCardType` | 文本 | 是 | Boss 使用的卡种 ID，必须已在 `Cards` 注册；AI 模式下必须是攻击卡，手动模式可用任意已注册卡种 |
| `playerControlsBoss` | 布尔 | 是 | 是否由玩家手动操作 Boss |
| `accumulateResources` | 布尔 | 是 | 资源是否跨回合累积；`false` 表示每回合开始清零 |
| `summoningSickness` | 布尔 | 是 | 新部署单位当回合是否不能行动 |
| `adjacentSwap` | 布尔 | 是 | 是否允许相邻己方单位互换位置 |
| `lineBlocking` | 布尔 | 是 | 是否开启同一行/列的单位遮挡 |

### 3.4 `Homes`：双方家（恰好 2 行）

| 列名 | 类型 | 必需 | 取值与含义 |
|---|---|---|---|
| `owner` | 文本 | 是 | 只能是 `player` / `boss`，且各出现一次 |
| `hp` | 整数 | 是 | 家的生命，≥ 1 |
| `produce` | 整数 | 是 | 家每回合产出，≥ 0；**Boss 家必须为 0** |

家坐标不填写：开局按“己方边缘中间行”自动定位，`playerSide` 决定左右与镜像。

### 3.5 `BossSlots`：AI 兵位（恰好 3 行）

| 列名 | 类型 | 必需 | 取值与含义 |
|---|---|---|---|
| `id` | 文本 | 是 | 兵位 ID，非空且互不重复（快照用它显示补兵计时） |
| `rowFraction` | 小数 | 是 | 行比例，0..1；内部行号 = 非负数四舍五入(`rowFraction × (rows − 1)`) |
| `edgeOffset` | 整数 | 是 | 从 Boss 区域靠玩家一侧向内数的列偏移，必须 ≥ 0 且小于 `homeRegionWidth` |

### 3.6 `Presentation`：表现参数（恰好 1 行）

| 列名 | 类型 | 必需 | 取值与含义 |
|---|---|---|---|
| `referenceWidth` | 整数 | 是 | UI 参考分辨率宽，≥ 1 |
| `referenceHeight` | 整数 | 是 | UI 参考分辨率高，≥ 1 |
| `fontSize` | 整数 | 是 | 基准字号，≥ 1 |
| `logLimit` | 整数 | 是 | 界面保留的日志条数上限，≥ 1 |
| `moveSeconds` | 小数 | 是 | 移动动画时长（秒），≥ 0 |
| `feedbackSeconds` | 小数 | 是 | 受击/反馈动画时长（秒），≥ 0 |
| `selectedScale` | 小数 | 是 | 选中放大倍率，> 0 |
| `playerColor` | 文本 | 是 | 玩家方颜色，`#RRGGBB` 或 `#RRGGBBAA` |
| `bossColor` | 文本 | 是 | Boss 方颜色，同上 |
| `resourceColor` | 文本 | 是 | 资源卡颜色，同上 |
| `attackColor` | 文本 | 是 | 攻击卡颜色，同上 |
| `specialColor` | 文本 | 是 | 特殊卡颜色，同上 |
| `moveColor` | 文本 | 是 | 可移动高亮颜色，同上 |
| `attackTargetColor` | 文本 | 是 | 可攻击高亮颜色，同上 |
| `swapColor` | 文本 | 是 | 可互换高亮颜色，同上 |
| `deployColor` | 文本 | 是 | 可部署高亮颜色，同上 |

颜色必须写成 `#RRGGBB` 或 `#RRGGBBAA`（十六进制，`#` 开头的 6 位或 8 位），不要使用颜色名或函数。

## 4. 常见错误速查表

| 现象（工具报出的原因） | 原因 | 修法 |
|---|---|---|
| `未声明的工作表（可用表：Cards/Deck/Rules/Homes/BossSlots/Presentation）` | 工作簿里多了复制粘贴残留的表 | 删除多余工作表，或把数据并回正式表 |
| `缺失必需工作表` | 表名拼写不一致（如 `Cards ` 带空格）或被删除 | 使用 `Tools/Spotlight/生成默认工作簿` 重新生成后再填写 |
| `未定义列：xxx` | 表头多了一列或列名拼错 | 对照第 3 节删除该列/改正列名 |
| `缺失必需列：xxx` | 必需列被删除或改成了别的名字 | 恢复该列并填入数据 |
| `重复表头：xxx` | 同一列名出现两次 | 删除重复列 |
| `该列有数据但没有表头` | 表头行漏写，数据落在无名列 | 补上表头或删除该列数据 |
| `工作表缺失或没有任何行` | 整张表是空的（连表头都没有） | 重新生成默认工作簿或补上表头 |
| `正式数据区禁止使用公式` | 单元格写了公式（含共享公式） | 改为常量；需要计算时在表格外的空白区域算好再粘贴数值 |
| `单元格为错误值` | 单元格是 `#REF!` / `#DIV/0!` 等 | 修正或清除该单元格 |
| `禁止合并单元格（范围 …）` | 表头或数据区存在合并区域 | 取消合并，把值填在左上角单元格 |
| `xxx 的值 'abc' 不是合法的整数` | 整数列里写了文字或小数 | 填整数；小数位去零 |
| `xxx 的值 'x' 不是合法的小数` | 小数列里写了文字 | 填数字，小数点用 `.` |
| `xxx 的值 '是' 不是合法的布尔值（true/false）` | 布尔列写了中文 | 改为 `true` / `false`（或 `1` / `0`） |
| `必需列为空：name` | 必需列留空 | 补值；不需要该卡种时删除整行 |
| `Cards 行 N (id)：id 须唯一且为字母开头的字母/数字/_/-` | ID 重复、以数字开头或含空格等非法字符 | 改成唯一的字母开头 ID |
| `Cards 行 N (id)：名称为空或重复` | 名字为空，或去掉首尾空格后与其他卡种同名 | 改成不重复的名字 |
| `Cards 行 N (id)：category 非法` | 分类不是 `resource`/`attack`/`special` | 改成三个合法值之一（小写） |
| `Cards 行 N (id)：生命必须正数，其他数值不得为负` | `hp` 为 0/空，或某数值列为负 | 生命填 ≥ 1 的整数，其余填 ≥ 0 |
| `Cards 行 N (id)：资源字段需要 resourceComponent` | 填了 `produce`/`upkeep` 却把 `resourceComponent` 关掉 | 打开 `resourceComponent`，或把两个数值清零 |
| `Cards 行 N (id)：部署扩展需要 teleportComponent` | `permitsAttackDeploy=true` 但 `teleportComponent=false` | 打开 `teleportComponent`（星门类卡牌） |
| `Cards 行 N (id)：仅资源卡可覆盖升级` | 攻击卡/特殊卡把 `requiresUpgrade` 设为 `true` | 只有资源卡可以覆盖升级 |
| `Cards 行 N (id)：未启用升级却填写 upgradeFrom` | `requiresUpgrade=false` 却填了来源 ID | 清空 `upgradeFrom` |
| `Cards (id) upgradeFrom：必须引用其他资源卡` | 来源 ID 不存在、指向自己或指向非资源卡 | 填另一张资源卡的 `id` |
| `Cards 行 N (id)：viewKey 不能为空` | 外观模板键留空 | 填 `default` 或已有模板键 |
| `Deck (id)：数量、卡种或重复条目非法` | 引用了不存在的卡种、数量为负、同卡种重复 | 改引用、改数量或合并成一行 |
| `Rules：棋盘至少 1 行 2 列，格数不能溢出` | `rows`/`columns` 太小或过大 | 行 ≥ 1、列 ≥ 2，且行×列不超过整数上限 |
| `Rules homeRegionWidth：必须在 1 至列数之间` | 区域宽度大于列数或小于 1 | 填 1..`columns` |
| `Rules：次数/资源不可为负，bossRespawnDelay 至少为 1` | 某个次数/资源为负，或补兵间隔为 0 | 次数与资源 ≥ 0，补兵间隔 ≥ 1 |
| `Rules playerSide：只能为 left/right` | 填了 `Left`、`左边` 等 | 填小写 `left` 或 `right` |
| `Rules firstSide：只能为 player/boss` | 填了其他值 | 填小写 `player` 或 `boss` |
| `Rules bossCardType：AI 必须使用攻击卡，手动模式必须使用已注册卡种` | Boss 卡种未注册，或 AI 模式下填了非攻击卡 | 先把卡种加入 `Cards`；AI 模式改用攻击卡 |
| `Homes：阵营唯一、生命正数、产出非负且 Boss 产出为零` | 少了 player/boss 某一行、家了重复、生命 ≤ 0 或 Boss 家产出不为 0 | 保证两行且数值合法 |
| `BossSlots：ID、行比例或边缘偏移非法` | 兵位 ID 为空/重复、`rowFraction` 超出 0..1、`edgeOffset` 为负或不小于 `homeRegionWidth` | 按第 3.5 节修正 |
| `Presentation：尺寸/字号/日志数/动画参数非法` | 某整数 ≤ 0，动画时长为负，放大倍率 ≤ 0 | 按第 3.6 节修正 |
| `Presentation xxx：需要 #RRGGBB 或 #RRGGBBAA` | 颜色写成了颜色名或缺少 `#` | 改为 `#RRGGBB` / `#RRGGBBAA` |
| `找不到工作簿，请先执行 Tools/Spotlight/生成默认工作簿` | 工作簿被移动或删除 | 重新生成，或把文件放回 `Assets/Spotlight/Config/Spotlight.xlsx` |
| 配置门禁提示“配置已过期” | 编辑工作簿后没有重新编译 | 执行 `Tools/Spotlight/编译全部配置` |
| 配置门禁提示“生成资产缺失/不匹配” | 手工删除或改动了 `Assets/Spotlight/Generated/` 内容 | 重新编译；不要手工编辑生成产物 |

## 5. 有效与无效示例

有效（`Cards` 片段，表头必须齐全）：

```text
id,name,category,viewKey,hp,atk,range,moveDistance,produce,upkeep,resourceComponent,teleportComponent,permitsAttackDeploy,deployHomeOnly,avoidAdjacentSameType,requiresUpgrade,upgradeFrom
ge1,GE-1开采机,resource,default,1,0,0,0,1,0,true,false,false,false,false,false,
ge12,GE-12开采机,resource,default,1,1,1,0,1,0,true,false,false,false,false,true,ge1
```

无效（会被逐条报错）：

```text
ge-1,GE-1开采机,Resource,default,0,-1,0,0,0,0,false,false,false,false,false,false,   → hp 为 0、category 大写、负攻击力、资源字段与开关冲突
ge1,GE-1开采机,resource,default,1,0,0,0,1,0,true,false,false,false,false,true,ge1     → requiresUpgrade 仅资源卡目标合法，但 upgradeFrom 指向自己
ge12,GE-1开采机,attack,,1,0,0,0,0,0,false,false,true,false,false,false,             → 名字重复、viewKey 为空、攻击卡不可覆盖升级、permitsAttackDeploy 缺 teleportComponent
```
