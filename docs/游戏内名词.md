# 游戏内名词

本文件是 Spotlight 全部机制与身份的**统一命名来源**。设计文档、代码注释、界面文案、日志与测试用例必须沿用这里的中文名与英文标识符；新增机制时先在此登记，再写实现。

> 代码位置：规则内核见 `Assets/Spotlight/Core/`，运行层见 `Assets/Spotlight/Runtime/`。名词后的反引号标识符是对应类型或字段，供代码检索。

## 1. 卡牌流转区域

玩家的一局游戏中，可循环的卡牌只有三种存放区域，统称**牌堆三区**。同一张卡的卡牌记录在任一时刻只存在于其中一个区域。

| 中文名 | 英文 / 代码 | 说明 |
|---|---|---|
| 卡组 | Deck（已废除） | **旧概念**：原 `Deck` 工作表与 `DeckRow` 按卡种填张数，两者已删除。同一个词现在只用于描述“玩家本次携带的卡种集合 + 由此生成的抽牌堆清单”，规则见第 5 节；运行中的卡牌来源一律叫“抽牌堆”。 |
| 抽牌堆 | DrawPile（`GameSnapshot.DrawPile`） | 玩家每回合抽取卡牌的来源。抽牌堆为空时才触发墓地洗回。**不得再称为“牌库”**。 |
| 手牌 | Hand（`GameSnapshot.Hand`） | 已抽到、尚未打出的卡。手牌不参与墓地洗回，也不会被复制。 |
| 墓地 | Graveyard（`GameSnapshot.Graveyard`） | 玩家**已使用**的卡牌存放处：成功部署的卡与主动弃置的卡都进入这里。抽牌堆耗尽时，墓地整体洗牌并转入抽牌堆，继续本次抽牌。**“已使用牌堆”统一叫“墓地”**。 |
| Boss 回收区 | BossGraveyard（`GameSnapshot.BossGraveyard`） | Boss 单位阵亡后的独立回收区，不参与玩家的洗回，永远不进入玩家的抽牌堆或墓地。 |

流程约定：

- 一张玩家卡的生命周期为：携带选择 → 抽牌堆 → 手牌 →（成功部署）→ 墓地 →（抽牌堆耗尽时洗回）→ 抽牌堆 → ……，可无限循环。
- **成功部署的那一刻，卡牌记录就进入墓地**，而不是等到单位阵亡或被覆盖升级。
- **单位阵亡或被覆盖升级时不再回收来源卡**，否则同一张卡会重复入堆、导致牌堆膨胀。
- 主动弃牌（弃牌阶段）同样进入墓地；手牌上限以内的牌不参与洗回。
- 抽牌堆与墓地同时为空时允许少抽，不额外生成新牌；日志记录实际抽取数量与缺额。

## 2. 卡牌相关身份

同一“张”卡在规则里有两套完全分离的身份，**不可混用**：一套是可循环的卡牌记录，一套是场上的战斗单位。

| 中文名 | 英文 / 代码 | 说明 |
|---|---|---|
| 卡牌记录 | `CardRecord` | 只含实例 ID（`Id`）、卡种 ID（`TypeId`）与阵营（`Owner`）的不可变记录，在抽牌堆、手牌、墓地之间流转。它是唯一会被洗回和再次抽到的身份。 |
| 战斗单位 | `UnitState` | 一次成功部署产生的可变实体。字段包括单位 ID（`Id`）、来源卡牌 ID 的值副本（`SourceCardId`）、卡种（`TypeId`）、阵营（`Owner`）、位置（`Position`）、当前生命（`Hp`）、生命上限（`MaxHp`）、当前攻击力（`Attack`）、当前射程（`Range`）、当前移动距离（`MoveDistance`）、一次性部署减攻状态（`DeploymentPenaltyPending` / `DeploymentAttackReduction`）、行动状态（`Acted`）、维持费支付（`UpkeepPaid`）、部署顺序（`DeploymentOrder`）与兵位（`BossSlotId`）。 |
| 家 | `HomeState` | 独立实体，不进入抽牌堆、不参与互换、没有攻击力，可被攻击与移动；ID 为负数（玩家 -1、Boss -2）。 |

关键约束：

- `UnitState` **只保存来源卡牌的值副本，不持有 `CardRecord` 引用**。因此场上的单位与抽牌堆、手牌、墓地中的卡牌互不影响。
- 同一张卡牌记录可以反复洗回、再次部署，在场上**同时存在多个互相独立的单位**：它们各自满血、各自行动、各自计算产出与维持费。
- 单位不把伤势、位置或行动状态写回卡牌；重新部署总是按配置恢复初始生命与初始攻击力等基础属性。
- **场上战斗属性**（当前生命与上限、当前攻击、射程、移动距离）只属于 `UnitState`：部署时从只读卡种配置初始化，之后只由规则代码修改。伤害、合法动作、AI 与刷怪条件一律读当前值，手牌与牌堆中的卡牌仍展示卡种基础配置。
- 每次部署创建的新单位 ID 必须与原单位不同；覆盖升级后旧单位身份作废。

## 3. 操作与阶段

| 中文名 | 英文 / 代码 | 说明 |
|---|---|---|
| 部署 | Deploy（`CommandKind.Deploy` / `BossDeploy`） | 把手牌或 Boss 卡放到棋盘，成功即消耗一次出牌次数并让来源卡进入墓地。 |
| 移动 | Move（`CommandKind.Move`） | 单位在本回合向上/下/左/右走至多移动距离格，走最短可通行路径。 |
| 移动家 | MoveHome（`CommandKind.MoveHome`） | 家在己方区域内移动一格。 |
| 攻击 | Attack（`CommandKind.Attack`） | 按曼哈顿距离对单位或家造成伤害。 |
| 互换 | Swap（`CommandKind.Swap`） | 相邻己方非资源单位交换位置，双方同时消耗行动机会；资源卡不参与互换，既不能发起也不能作为目标。 |
| 离场 | Withdraw（`CommandKind.Withdraw`） | 玩家主动把自己在场的单位移出棋盘：不消耗该单位本回合行动，来源卡不回收（部署时已进墓地），Boss 单位与家不可离场。 |
| 弃牌 | Discard（`CommandKind.Discard`） | 弃牌阶段把手牌弃至上限，被弃的卡进入墓地。 |
| 结束回合 | EndTurn（`CommandKind.EndTurn`） | 交出行动权；手牌超限时先进入弃牌阶段。 |
| 弃牌阶段 | MatchPhase.Discard（`MatchPhase.Discard`） | 手牌超过上限时必须弃至上限才能进入对方回合。 |
| 覆盖升级 | Upgrade（`requiresUpgrade` + `upgradeFrom`） | 资源卡只能覆盖指定类型的己方资源单位；只移除旧单位，不重复回收来源卡。 |

## 4. 数值与特殊机制

| 中文名 | 英文 / 代码 | 说明 |
|---|---|---|
| 维持费 | upkeep | 单位每个己方回合开始的持续消耗；不足时本回合不能行动。 |
| 产出 | produce | 家或资源卡每回合提供的资源。 |
| 召唤失调 | summoningSickness | “刚上场不能行动”的规则开关；Boss 兵位首次部署是唯一豁免入口。 |
| 星门 | Teleport / `permitsAttackDeploy` | 特殊卡，只能部署在己方区域，为四邻格提供战斗卡部署扩展，并禁止与同卡种四邻部署。 |
| 兵位 / 补兵 | `BossSlotRow` / `BossReplacement` | Boss 的固定兵位独立计时，一阶段阵亡后按补兵间隔重新部署，二、三阶段暂停补兵。 |
| 延迟十字炸弹 | `BossBombState` | Boss 技能产生的独立地面标记，不属于卡牌记录、战斗单位或家，不占格也不能被攻击；玩家行动前部署，下一完整回合玩家行动前爆炸。 |
| 炸弹部署机会 | `BossBombPending` | 玩家行动前、技能间隔到期时的一次独立机会，不消耗普通放牌次数、不累计；手动模式必须先布置或跳过才能开始玩家普通操作。 |
| 爆炸搜索步骤 | `BombBlastStep` | 一次爆炸实际访问的格子及该格伤害/阵亡结果，只供日志与动画读取，不允许表现层重新结算。 |
| 普通刷怪笼（显示名“刷怪卡”） | `UnitState.IsBossSpawner` | Boss 一阶段技能部署的特殊战斗单位，该技能同时最多一张；标志只用于技能唯一性，刷怪由能力配置决定；固定不动、不能攻击或互换，可被摧毁。从部署后的下个 Boss 回合起在八邻生成战机。 |
| 刷怪卡部署机会 | `BossSpawnerPending` | Boss 回合开始满足压力条件时获得，不消耗普通放牌次数、不累计；手动模式先部署或跳过再普通行动。 |
| 战机 | `ISpawnConfig.SpawnCardType` | 刷怪卡生成的 Boss 攻击类单位，默认复用 `bossCombat`；独立身份、满血、遵守召唤失调，不占固定兵位。 |
| 顶替 | `spawn-replace` | 刷怪卡八邻无空格时，随机移除一个邻接玩家单位并在原格生成战机；不比较生命、不重复回收来源卡，家与 Boss 单位不可顶替。 |
| 一次性部署减攻 | `deploymentPenaltyComponent` / `deploymentAttackReduction`（`IDeploymentPenaltyConfig` / `DeploymentPenaltyComponent`） | 按配置启用的被动能力：具有该能力的单位成功上场后获得**一次**未消耗效果（`DeploymentPenaltyPending=true`）。随后同阵营、早于它上场的攻击类卡牌成功上场时，按 `DeploymentOrder` 升序取最早的一个来源，把新单位当前攻击力降低来源的减攻量（下限 0），并把来源标记为已消耗。减攻持续到目标离场；无来源或目标不是攻击类时不消耗。能力不占行动次数，召唤失调、已行动与维持费不足都不阻止触发；未触发效果随来源离场而消失，离场后不恢复目标攻击力。 |
| 一次性减攻量 | `DeploymentAttackReduction` | 单位上场时从卡种配置复制的减攻值；没有该能力时为 0。规则代码不得把它写死为任何具体数字。 |
| 部署消耗 | `deployCost` | 卡牌级通用属性：成功部署这张卡时一次性从玩家资源中扣除的点数，0 表示免费。资源不足时该目标不合法、不会高亮，失败不扣资源也不消耗手牌；Boss 没有资源系统，Boss 部署不检查该值。 |
| 邻域部署要求 | `deployRequireAdjacentCategory` / `deployRequireAdjacentCount` | 卡牌级部署限制：目标格四邻（上下左右）中指定分类（resource/attack/special）的在场单位数量必须不小于配置值。只统计战斗单位，不含家，不区分阵营；数量不足时该格不合法。 |
| 入场标记 | `markOnEnterComponent` / `markOnEnterRadius`（`IMarkOnEnterConfig` / `MarkOnEnterConfigSO`） | 按配置启用的被动能力：具有该能力的单位上场时，把半径内（半径 1 = 3×3 八邻、不含自己）的其它单位标记为**自己阵营**；其它单位移动或互换进入范围时同样被标记。标记永久保留（来源离场、目标离开范围都不撤销），多来源重叠先到先得、不叠加。 |
| 标记奖励 | `markRewardResource` / `UnitState.MarkedBy` / `UnitState.MarkReward` | 被标记单位**因战斗阵亡**（`Removal.Death`）时，标记者阵营立即获得配置的资源；主动离场、被覆盖升级、被战机顶替都不发放。奖励在标记时从来源配置复制，来源之后离场或改配置都不影响已标记的单位。Boss 侧暂无资源系统，Boss 标记不产生资源。 |
| 死亡加攻 | `deathGrowthComponent` / `deathGrowthPerKill`（`IDeathGrowthConfig` / `DeathGrowthConfigSO`） | 按配置启用的被动能力：**全棋盘任一单位因战斗阵亡**时，在场且未达上限的该能力单位攻击力增加配置值。加成永久保留、跨回合与来源无关；主动离场、被覆盖升级、被战机顶替都不触发。 |
| 死亡加攻次数上限 | `deathGrowthLimit` / `UnitState.DeathGrowthTriggers` | 该能力最多触发的次数（不是攻击力上限）。达到后继续有单位阵亡也不再增加；已获得的加成不回收。 |
| 治疗型攻击 | `attacksAlliesAsHeal` / `LegalActions.Heal` | 卡牌级开关（仅攻击类卡可启用）：该单位的合法攻击目标额外包含**己方单位**（不含自己与家），对友方的攻击结算改为治疗。`LegalActions.Heal` 只是把这类目标单列给视图染色，它们同时仍在 `Attack` 里，点击链路与敌方目标一致。 |
| 治疗结算 | `min(生命上限, 当前生命 + 当前攻击)` | 对友方目标时以当前攻击力作为治疗量，受生命上限限流；满血允许白打并照常消耗行动。治疗不会触发阵亡判定，也不产生伤害。 |
| 即时卡 | `leaveAfterDeploy` / `deployGainResource`（`IInstantEffectConfig` / `InstantEffectConfigSO`） | “部署即结算、结算即退场”的功能卡（特殊卡）。仍需合法且为空的部署格；成功部署后立即获得 `deployGainResource` 资源，随后离场。在场时间视为 0：不参与一次性部署减攻、不参与入场标记。Boss 卡种与刷怪卡卡种不得指向即时卡。 |
| 结算后离场 | `Removal.Consumed` | 即时卡效果结算完成后的自动移除原因。与阵亡、被覆盖升级、被战机顶替、主动离场并列：日志写“结算后离场”，**不启动补兵计时、不触发死亡加攻与标记奖励**。 |
| 四邻空格限制 | `adjacentClearanceComponent` / `adjacentClearanceMinEmpty`（`IAdjacentClearanceConfig` / `AdjacentClearanceConfigSO`） | 按配置启用的被动能力（后羿-II综合舰，阈值 2）：该单位在场时，上下左右四邻中至少要有 N 格为空（斜角不计，棋盘外按空计算，家和战斗单位算占用，炸弹不占格）。**部署**只检查目标格；**移动**同时检查起点（原布局）与落点（旧格已腾空、新格已占用的最终布局）；**互换**检查交换前、交换后两份布局，且双方中所有具有该能力的单位都要满足。路径中间格不检查。被围后仍可攻击，只是不能移动与互换；其它单位可以靠近把它围住，不会撤销那些单位的行动。 |
| 击杀恢复行动 | `killActionComponent`（`IKillActionConfig` / `KillActionConfigSO`） | 按配置启用的被动能力（维京长船-2056，无数值参数，非空配置即启用）：该单位的一次**直接攻击**（含伤害标记追加）使目标战斗单位死亡后，恢复该单位一次普通行动（`Acted=false`），可连续触发、无每回合次数上限。恢复不是重开回合：不抽牌、不产资源、不重复扣维持费、不恢复其它单位、不增加出牌次数；未使用的机会不跨回合保存。炸弹击杀、其它单位击杀、主动离场、覆盖升级与战机顶替都不会触发。 |
| 伤害标记 | `damageMarkComponent` / `damageMarkDamagePerStack`（`IDamageMarkConfig` / `DamageMarkConfigSO`） | 按配置启用的被动能力（SNP-EU，每层 1 点）：该单位**直接攻击存活战斗单位**后给目标加 1 层；家不挂层，治疗与炸弹不挂层，追加伤害不挂层。层**永久保留**（来源离场、跨回合、移动、互换、治疗都不清除），可同源/多源叠层、不设玩法上限；每层在施加时复制配置数值，之后不随配置或来源变化。 |
| 伤害标记层 | `DamageMarkLayer` / `UnitState.DamageMarkLayers` / `UnitState.DamageMarkBonus` | 目标身上的一层永久状态，保存施加时的每层追加伤害副本。`DamageMarkBonus` 是下次直接受伤将追加的总量（宽类型累加后截断）。层随单位移除而消失；重新部署同卡不继承旧层。与“入场标记 `MarkedBy`”是两种不同机制，不得混用字段或展示名。 |
| 直接伤害 / 追加伤害 | `DamageKind`（`DirectAttack` / `Bomb` / `MarkBonus`） | 直接伤害是普通攻击与炸弹每轮的基础扣血；追加伤害是目标已有伤害标记触发的扣血。追加伤害**不递归**（不再触发标记、不再追加、不挂新层），炸弹追加**不消耗炸弹预算**；任一步归零立即停止并只做一次死亡处理。 |
| 伤害归属 | `DamageContext` / `DamageResult` | 每笔伤害记录来源阵营、来源单位（炸弹为空）、目标、本笔类型与**根类型**；追加伤害沿用触发它的根来源（炸弹追加仍归炸弹，不会记到最初施加标记的单位），`DamageResult.Killed` 只表示本次整组伤害造成的击杀，供击杀恢复与 AI 判断。 |
| 快照 | `GameSnapshot` | 规则状态的只读副本，UI、日志与调试面板的统一数据源；持有旧快照不会受后续命令影响。 |
| 生成资产 | Generated assets | `Assets/Spotlight/Generated/` 下只读的 SO 与 Prefab，禁止手工修改。 |

## 5. 抽牌堆与携带选择

抽牌堆不再是“每种卡几张”的静态清单，而是由“携带选择 + 抽牌堆规则”推导出的运行时结果。原 `Deck` 工作表与 `DeckRow` 已删除；`DeckEntry` 只表示**最终抽牌堆清单里的一种卡 + 张数**。

| 中文名 | 英文 / 代码 | 说明 |
|---|---|---|
| 抽牌堆规则 | DeckConfig（`Rules.drawPileSize` / `tierRatio*` / `maxTypes*`） | 7 个数值：抽牌堆总张数、初/中/高级比例、初/中/高级携带上限（单位是**卡种数量**，不是张数）。规则层（`GameSession`）不读它，只在构牌、选卡与配置校验时使用。 |
| 抽牌堆张数 | `drawPileSize` | 本次对局生成的卡牌记录总数，默认 24，至少 3。“抽牌堆 + 手牌 + 墓地”的张数恒等于它。 |
| 阶级比例 | `tierRatioBasic` / `tierRatioIntermediate` / `tierRatioAdvanced` | 三阶级张数占抽牌堆的百分比，默认 70 / 20 / 10；各自至少 1，合计必须为 100（不支持 0%）。 |
| 携带上限 | `maxTypesBasic` / `maxTypesIntermediate` / `maxTypesAdvanced` | 玩家每局最多携带的三阶级**卡种数量**，默认 5 / 3 / 2，各自至少 1。 |
| 有效携带上限 | `DeckConfig.EffectiveMaxTypes` | `min(配置上限, 该阶级卡种数)`：选卡界面按它判断能否继续勾选，配置校验按它判断分到的张数是否够用。 |
| 携带选择（选卡） | DeckSelectionState（`Runtime/UI/DeckSelectionPanel`） | 开局前勾选本次携带哪些卡种：每阶级至少 1 种、最多到有效上限。结果只存在于本次运行会话，不持久化。 |
| 默认选卡 | `DeckComposition.TryBuildDefault` | 每阶级按有效上限取满、顺序为 `Cards` 表顺序；用作启动初值、调试重开前的兜底，以及“当前选卡变非法”时的静默回退。 |
| 强制牌堆 | `DebugConfigDraft` 的调试用强制牌堆 | 调试专用：任一卡种填 > 0 即整体覆盖抽牌堆（与选卡结果无关），全 0 表示按选卡结果生成；仅本次运行会话有效，不写入任何资产。 |
| 抽牌堆清单条目 | `DeckEntry`（`GameConfiguration.Deck`） | 最终抽牌堆里的“一种卡 + 张数”，由选卡与构图算法推导，不再来自 Excel。 |

可携带卡种池不做静态配置：池子 = `Cards` 表里 `tier != none` 的全部卡种（`none` 仍是 Boss 专用）。

构图算法（Core 唯一实现 `DeckComposition.TryBuild`，四步）：

1. 每阶级 `raw = floor(抽牌堆张数 × 比例 / 100)`；
2. 每阶级至少 1 张（比例恒 ≥ 1，因此不会出现 0 张的阶级）；
3. 合计不足张数时，缺额**全部给初级**；合计超出（只可能由第 2 步抬升造成）时从张数最多的阶级扣，平手按高级→中级→初级，每阶级保底 1 张；
4. 把每阶级张数**均分**给该阶级已选卡种，余数按 `Cards` 表顺序发给靠前的卡种，因此每个被选卡种至少 1 张。

示例：24 张 @70/20/10 → 初级 18 / 中级 4 / 高级 2；张数为 3 时 → 1 / 1 / 1。

配置期还要求“按比例算出的每阶级张数 ≥ 该阶级有效携带上限”，否则会在 `验证配置` 阶段报错——目的是保证玩家把上限勾满时，每个被选卡种都能真的抽到。

开局流程：

- 启动后必先经过携带选择，确认后才开局；开局入口没有“取消”按钮。齿轮菜单的「选卡」会先弹二次确认（确认后当前对局重开），确认后重新选卡并按新卡组重开对局。
- 局内的“重开”与胜利界面的“再来一局”沿用本次已选卡组，不再弹选卡界面。
- 调试面板“应用并重开”若让当前选卡变非法，会静默回退默认选卡。
- 不做持久化：每次重新启动游戏都要重新选卡。

## 6. 卡牌阶级

- **卡牌阶级 `CardTier` / `Cards.tier`**：卡种的共享只读属性，分为初级（`basic`）、中级（`intermediate`）、高级（`advanced`），独立于资源 / 攻击 / 特殊分类。每种玩家卡必须且只能有一个阶级。
- Boss 专用卡使用 `none`（不适用），不属于第四种玩家阶级；`none` 卡种不出现在携带选择里，因此不能进入抽牌堆。卡种可同时被 Boss 引用，Boss 引用本身不改变该卡的阶级。
- 阶级决定抽牌堆构图（见第 5 节）：每阶级的张数由抽牌堆张数与阶级比例算出，再均分给该阶级已选卡种。张数按卡牌张数累计——3 张同种初级卡计作 3 张初级卡。
- 携带限制作用在**卡种数量**上：每局最多携带 `maxTypes*` 种（有效上限 = min(配置上限, 该阶级卡种数)），且每阶级至少选 1 种。每阶级至少要有 1 个可携带卡种，否则配置校验报错；携带上限不限制部署回合。
- 参考表中的“后期”统一命名为“高级”；不建立基本包、进阶包等卡组包分类。
- 当前划分：初级为 GE-1、GE-12、尖刀1、灵兔2、奥德修斯-1、京都壹号；中级为开普勒-I、开普勒-II、星铆-1复合着陆机、后羿综合舰、星棹-1收集系统、力场-I、比目鱼、战时储备；高级为星门。Boss敌兵与刷怪卡为不适用。
- Excel 与 JSON 缺失、空白或非法阶级必须提示补齐，不按卡名、数值或类型推断。卡牌记录和战斗单位通过卡种 ID 查询阶级，不重复保存该属性。
